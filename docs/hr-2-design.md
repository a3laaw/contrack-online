## 1) الفلسفة — نفس الأسس بلا استثناء

- **الموظف الموحد**: كل ما يأتي يعلّق على كيان `employees` القائم — لا كيان ثانٍ (G2).
- **النواة النقية أولًا**: كل الحسابات (نهاية الخدمة، المخصصات، دقائق التأخير، محلل البصمة) دوال نقية في `hr-constants.ts` + اختبارات bun — بلا DB ولا React (نمط consulting-v1).
- **خط واحد للمالية**: لا مصدر ثانٍ للأثر المحاسبي — قيود المسير ومخصصاته وتسوية النهاية كلها عبر `postJournalEntry` بمصادر `sourceType` معلنة.
- **البذر المؤجل (G3/G5)**: 2161/2211/5211 لا تُبذر بجدول ساكن — تُضمن آليًا لحظة أول قيد مخصصات يحتاجها (`ensureHrAccounts`) — فلا حساب ميت يضلل القوائم.
- **اللقطات المجمّدة**: أي رقم يدخل المسير (دقائق، أيام مرضية) يُكتب لقطة عند التوليد ولا يُقرأ لاحقًا (Cost Snapping).

## 2) قرارات تحتاج اعتمادك (القيم الافتراضية المقترحة — تُعدل عند الاعتماد)

| # | القرار | المقترح | البديل |
|---|--------|---------|--------|

| د4 | صيغة المكافأة (م53) | نصف أجر شهر عن كل سنة من الخمس الأولى + أجر شهر كامل عن كل سنة تالية + كسر السنة بنسبته + سقف 18 شهرًا — على **آخر أجر أساسي** حرفًا من نص القانون | صيغة «15 يومًا × (÷26)» |
| د5 | نطاق المخصصات | **تجميعي بمستوى الشركة** (لا تتبع فردي لرصيد مخصص كل موظف) — التسوية تستهلك رصيد الحساب وتصرف الفرق مصروفًا | تتبع فردي (تكلفة بناء أعلى بلا حاجة فعلية الآن) |
| د6 | استيراد البصمة | **CSV/TXT نصي** (قالب موثق يفتح ويحفظ من Excel — بلا مكتبات جديدة) | مكتبة xlsx للأرشيف الثنائي |

### 3.1 توسعات الجداول القائمة (بلا ترحيل)

  lateMinutes       Int    @default(0) @map("late_minutes")     // دقائق تأخير بعد السماحية — محسوبة آليًا من الجدول
  earlyLeaveMinutes Int    @default(0) @map("early_leave_minutes") // دقائق انصراف مبكر بعد السماحية

model PayrollRecord {
  // القائم: لقطة + baseAmount/absenceDeduction/advanceDeduction/netAmount
  snapSickDays    Decimal @default(0) @map("snap_sick_days")     // لقطة: أيام مرضية متقاطعة بالشهر
  snapLateMinutes Int     @default(0) @map("snap_late_minutes")   // لقطة: ∑ دقائق التأخير والانصراف القابلة للخصم
  sickDeduction   Decimal @default(0) @map("sick_deduction")     // مرضية بشرائح <100% (د2)
  lateDeduction   Decimal @default(0) @map("late_deduction")     // دقائق مجردة بعد الإعفاءات (د3)
}

model PayrollBatch {
  // القائم: totals + journalEntryId + paymentVoucherId + حالة موثقة
  provisionEntryId Int? @map("provision_entry_id") // قيد المخصصات المصاحب — يُعكس مع الإلغاء

model Setting {
  // القائم كاملًا يبقى — إضافات جدول الدوام الواحد:
  hrWorkStart  String @default("08:00") @map("hr_work_start")
  hrWorkEnd    String @default("17:00") @map("hr_work_end")

model EmployeePermission {   // إذن تأخير صباحي | انصراف مبكر — أخف من آلة الإجازات

  // unique ليس لازمًا: طلبان بنفس اليوم مسموحان لكن الإعفاء = ∑ المعتمدة بحدّ دقائق اليوم الفعلية

model EmployeeTermination {  // توثيق نهاية الخدمة — السيناريو + اللقطة + القيد

  wageAtEnd    Decimal @map("wage_at_end")     // لقطة آخر أجر أساسي

  entryId Int? @map("entry_id")   // قيد التسوية بعد الاستقرار — رابط مطلق

## 4) إعدادات الدوام والأذونات — ساعة السماحية

- **جدول الدوام**: حقول `Setting` الثلاثة (بداية/نهاية/سماحية) — بروفايل واحد للشركة. بلا رمضان ولا بروفايلات متعددة (حدود HR-2 §12) — ساعات اليوم مشتقة `end − start`.
- **الأذونات**: آلة أخف من الإجازات — `معلقة → معتمدة | مرفوضة` (الرفض بقرار موثق، تعديل/حذف للمعلقة فقط). الإذن لا ينشئ سجل حضور — هو **مُعفٍ** فقط.
- **قاعدة الخصم الدقائقي** (د3-أ، نواة نقية):
  1. تأخير اليوم = `checkIn − (start + سماحية)` بالدقائق (إن سالبة = صفر). الانصراف المبكر بالمثل مقابل `end`.
  2. الإذن المعتمد يعفي دقائق يومه الفعلية بحدّ مدة الإذن المعلنة.
  3. ما بقي من دقائق مجردة بالشهر → `lateDeduction = الدقائق × (الأساسي ÷ 30 ÷ ساعات اليوم)` — للأساس الشهري فقط (اليومي: لا أجر للوقت الغائب أصلًا — سلوك HR-1).
  4. بلا جدول دوام مضبوط؟ كل الدقائق = صفر (أمان — لا خصم بلا قاعدة معلنة).

## 5) استيراد البصمة — محلل نقي + تقرير معاينة

- **القالب**: `رقم وظيفي, التاريخ (YYYY-MM-DD), دخول, خروج, دخول2, خروج2` — CSV/TXT بفواصل `,` أو `;` وأوقات `HH:MM` متسامحة (`8:5` ⇒ `08:05`). قالب فارغ قابل للتنزيل من الشاشة.
- **المحلل النقي** (`hr-import-core.ts`):
  - دمج البصمات: دخول = الأبكر، خروج = الأحدث (البصمات الوسطى تُتجاهل — موثق).
  - الحالة: دخول+خروج ⇒ `present` (+دقائق التأخير/الانصراف من الجدول) · بصمة ناقصة ⇒ سجل بملاحظة «بصمة ناقصة» بلا دقائق · اثنان خاليان ⇒ يُتخطى.
  - يوم مغطى بإجازة معتمدة/بدأت ⇒ يُتخطى (الإجازة تسبق البصمة) — يظهر بالتقرير.
  - غير معروف الرقم الوظيفي ⇒ سطر مرفوض بسبب واضح.
- **التدفق**: POST `preview` (تحليل بلا كتابة + تقرير: صالح/محدث/تخطي-يدوي/مرفوض مع الأسباب) ← POST `commit` (upsert محكوم بد7). المصدر `source=import`.
- **قاعدة د7**: الأيام ذات `source=manual` تُعفى من الاستيراد نهائيًا — يظهر عددها بالتقرير.

## 6) حاسبة نهاية الخدمة — قوانين 41/44/51/53 (6/2010)

**النواة النقية** (`computeEOS`) — على آخر أجر أساسي (حقل `salary` القائم):

| السيناريو | الأساس القانوني | النتيجة |
|-----------|-----------------|---------|
| انتهاء عقد / فصل عادي | م53 | كامل: نصف شهر × سنوات الخمس الأولى + شهر × ما بعدها + كسر السنة بنسبته + سقف 18 شهرًا |
| استقالة | م51 | سلالم: <3 سنوات صفر · 3–5: الثلث · 5–10: الثلثان · ≥10: الكامل |
| فصل لسبب من م41 | م41 | **صفر** — الفصل للسبب القانوني يحرم المكافأة |
| انصراف لسبب من م44 | م44 | كامل (الانصراف مشروع — لم يُخل بالعقد) |
| وفاة | م53 | كامل (للورثة) |
| زواج (خلال 6 أشهر) / ولادة (خلال 3 أشهر) | م51 | كامل |
| اتفاق الطرفين | اتفاق | كامل كافتراضي — المبلغ قابل للتعديل قبل الاستقرار |

- **بدل الإجازات**: رصيد السنوي المعاد حسابه لحظة النهاية (نفس `recountAnnualBalance`) × قيمة اليوم (د1: ÷26) — سطر منفصل لا يدخل سقف المكافأة.
- **سنوات الخدمة**: `serviceYears(hireDate, endDate)` = سنوات كاملة + كسر السنة ÷365 — لقطة عند الحساب.
- **المعالجة**: توثيق `EmployeeTermination` بحالة **محسوبة** (قابل للإلغاء بسببه) ← زر **الاستقرار** (مدير): قيد تسوية + تعطيل الموظف — §8.
- **التقرير**: مطبوع بمسار الحساب كاملًا (السنوات، الكامل، السلم المطبق، السقف، البدل، الإجمالي) — للتوظيف في المخالصة.

## 7) محرك المخصصات — بذر مؤجل + قيد شهري مصاحب

- **البذر الآلي عند أول حاجة** (`ensureHrAccounts` — G3/G5):
  - `2161 مخصص إجازات الموظفين` (liability، شقيقة 2160) · `2211 مخصص نهاية الخدمة` (liability غير متداولة، شقيقة 2210) · `5211 مصروف مخصص نهاية الخدمة` (expense، شقيق 5210) — بعناصر XBRL موثقة وقابلة للضبط عند التدقيق.
  - الشركات الجديدة تدخلها شجرة البذرة نفسها؛ القائمة تُضمن آليًا عند أول قيد.
- **الاستحقاق الشهري** (نواة نقية، يُقيَّد لحظة اعتماد المسير — نفس تاريخه):
  - إجازات: `∑ الموظفين الشهريين: 2.5 يوم × (الأساسي ÷ 26)` — مدين **5210** / دائن **2161**.
  - نهاية خدمة: `∑ الموظفين: (نصف شهري إن الخدمة <5 سنوات، شهرية إن ≥5) ÷ 12` — مدين **5211** / دائن **2211**.
  - قيد واحد متزن `sourceType=payroll_provisions` مرتبط بـ`batch.provisionEntryId` — الإلغاء العكسي للمسير يعكس القيدين معًا (نمط الزكاة).
  - مستثنى: الموظفون المستثنون من المسير واليوميون (تُستقلى مكافأتهم عبر 5211 عند التسوية مباشرة — حدود موثقة).
- **استهلاك التسوية** (عند الاستقرار — مدير):
  - `مدين 2161 (بدل الإجازات حتى رصيد الحساب) + مدين 5210 (الفرق) + مدين 2211 (المكافأة حتى الرصيد) + مدين 5211 (الفرق) / دائن 2160 (الإجمالي)`
  - ثم الدفع النقدي عبر PV من 2160 — نفس آلية دفع المسير القائمة، بلا بنية جديدة.

## 8) تحصينات HR-1 المؤجلة (بنود §0-6)

- **منع SD الصارم**: سند SD يدوي لموظف مشمول بمسير غير ملغى لشهره ⇒ **403 عربي** (بدل التحذير الحالي) — الحارس في مسار السندات نفسه.
- **الخصم الفعلي للشرائح المرضية**: إجازة مرضية متقاطعة مع الشهر بشريحة <100% ⇒ `sickDeduction = الأيام المتقاطعة × (الأساسي ÷ 30) × (1 − النسبة)`. `sickTier` القائم يكفي (اللقطات القديمة بلا شريحة = كامل الأجر). `deductionTotal` للدفعة يصبح `absence + sick + late` — تُثبَّت الحسابات باختبارات نواة قبل الربط.

## 9) الواجهة والشل والصلاحيات

- **الشل**: تبويب HR يزداد 3 بنود بعد «السلف»: `الأذونات` (Clock) · `نهاية الخدمة` (DoorOpen) · `التقارير` (ClipboardList) — `perm: screen_hr` للجميع، إخفاء تلقائي لغير المفعّل عبر `navModulesFor`.
- **HRView** — أقسام جديدة بنمط الأقسام القائمة:
  - **الحضور**: زر «استيراد بصمة» بحوار من مرحلتين (اختيار ملف نصي ← معاينة التقرير ← تثبيت) + حوار «جدول الدوام» (الحقول الثلاثة) + عمودا الدقائق الجديدان.
  - **الأذونات**: بطاقة طلب + تبويبات حالة + اعتماد/رفض بقرار موثق (نمط الإجازات حرفيًا).
  - **المسير**: أعمدة المرضية والتأخير بالسجلات + «قيد المخصصات» ظاهر في توقيع الاعتماد.
  - **نهاية الخدمة**: حوار حساب (موظف + تاريخ نهاية + سيناريو) يعرض الحسبة قبل التوثيق + قائمة الموثقات بحالاتها + زر الاستقرار للمدير + تقرير مطبوع.
  - **التقارير**: تقرير ملف الموظف (بيانات + رصيد + حضور شهري مجمّع + إجازات + أذونات + سجلات مسايره + سلفه وأرصدته + نهاية خدمته) + مصفوفة حضور شهر (موظف × أيام) + سجل نهاية الخدمة — كلها بطباعة `window.print` بترويسة الشركة.
  - ملاحظة تنفيذية: إن تضخم HRView (تجاوز ~4000 سطر) تُستخلَل الأقسام الجديدة لمكونات داخلية بمجلد `hr/` — قرار كود لا يغير التصميم.
- **الصلاحيات**: بلا مفاتيح جديدة — `screen_hr` يغطي، الاستقرار/الاعتماد المالي للمدير (`isSuperRole`) كما في HR-1، و`moduleGuard("hr")` على كل مسار جديد.

## 11) خطة التنفيذ والاختبارات (بعد الاعتماد)

1. **السكيما**: توسعات §3 + الجدولان + `db:push` + TENANT_MODELS/BACKUP_MODELS بنفس الـcommit.
2. **النوى النقية + الاختبارات**: `hr-constants.ts` يتوسع (دقائق/مرضية فعلية) + `hr-eos-core.ts` + `hr-import-core.ts` + `hr-provision-core.ts` — كلٌّ بملف اختبار قبل أي ربط.
3. **الخادم**: مسارات `api/hr/{permissions,attendance/import,eos,schedule,reports/*}` + تعديل اعتماد المسير (قيد المخصصات) + حارس SD الصارم — audit في كل حركة.
4. **الواجهة**: أقسام §9 + الشل.
5. **تحقق حي** (شركة بذر مؤقتة ثم تنظيف كامل): قالب بصمة يستورد بدقائق صحيحة ← إذن معتمد يعفي ← مسير بخصم مرضية/تأخير متزن ← قيد مخصصات متوازن ← توثيق نهاية خدمة استقالة 6 سنوات (ثلثا) ← استقرار بقيد يستهلك المخصصين ← PV من 2160 ← موبايل 375 صفر أخطاء.
6. **push ومراجعة الإنتاج** — النشر التلقائي عبر main.

## 12) حدود HR-2 (ما لا يُبنى عمدًا)

- بلا XLSX ثنائي ولا أجهزة API مباشرة (CSV/TXT نصي — د6) · بلا بروفايلات دوام متعددة ولا رمضان ولا عطل رسمية آلية (الإدخال اليدوي يغطيها بحالة «عطلة») ·
- بلا تتبع فردي لرصيد المخصص لكل موظف (د5 تجميعي) · بلا تدقيق ملف حقلًا-بحقل (د9 → HR-3) · بلا تكلفة عمالة على العقود ولا أطقم (HR-3) ·
- بلا توظيف/applications · بلا إشعارات/تطبيق موبايل · المسير والمخصصات لا يلمسان الزكاة أو iXBRL (الشجرة القائمة تكفي، العناصر XBRL للحسابات الجديدة تستفيد لاحقًا تلقائيًا).

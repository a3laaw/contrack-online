# تصميم ر5 — بوابة العميل · رابط الكشف المؤقت الآمن — ConTrack Online

> وثيقة تصميم للاعتماد — بلا أي كود. المرجع: موديول **Portal** في خريطة Odoo المعتمدة (`docs/odoo-modules-reference.md` §2: بوابة العملاء/الموردين — بلا حسابات كاملة ولا مفاتيح API ولا سحب ملفات) + الخارطة المعتمدة (`docs/development-roadmap.md` ر5: تصنيف C جديد — «رابط خارجي مؤقت برمز آمن — لا حسابات كاملة أولًا» — **أعلى مخاطرة أمنية في القائمة → مرحلتان**).
> المحركات القائمة الجاهزة للاستثمار: **الكشف الشامل للعميل** (`buildCustomerStatement` + `statement-html` + `renderHtmlToPdf` — ر2، خادمي ومجرَّب في الإنتاج) + **ملف العميل الموحد** بأربعة تبويبات (ر2) + حرس لكل مسار (`authGuard`) بلا middleware عام.
> **الحالة: بانتظار موافقة المالك — النطاق للتنفيذ الآن: المرحلة أ حصرًا (الرابط المؤقت لكشف PDF). المرحلة ب (صفحة بوابة كاملة) مسودة مبدئية تُنفَّذ لاحقًا بأمر المالك حصرًا (§7).**

## 0) النطاق — مرحلتان والأمان أولًا

| # | البند | الوضع الحالي | المرحلة أ (هذا الاعتماد) | المرحلة ب (لاحقًا بأمر المالك) |
|---|-------|--------------|---------------------------|--------------------------------|
| 1 | سؤال العميل عن المستحقات | مكالمة/واتساب لموظف الشركة ← فتح النظام ← توليد كشف ← إرساله يدويًا | زر **«رابط كشف مؤقت»** في ملف العميل يولّد رابطًا آمنًا يفتح **كشف PDF** للعميل نفسه **بلا دخول النظام** — يُنسخ ويُشارك واتساب/SMS فورًا | صفحة بوابة عامة بملخص المستحقات والدفعات |
| 2 | هوية العميل | لا حسابات للعملاء **قصدًا** (العملاء ليسوا مستخدمين) | الرمز نفسه هو الهوية — 256-bit عشوائي يُخزَّن هاشًا، بلا كلمة مرور ولا تسجيل | نفس الرمز يفتح الصفحة بدل الملف مباشرة |
| 3 | التحكم بالوصول | — | صلاحية محدودة + إبطال يدوي فوري + تتبع آخر استخدام | نفس القواعد حرفيًا |
| 4 | ما يُعرض | — | كشف حساب ذلك العميل حصرًا (نفس كشف ر2) — لا عقود ولا مرفقات ولا BOQ ولا أي كتابة | مؤشرات + دفعات مستحقة + أزرار كشوف — قراءة فقط |

**ما لا تدخله المرحلة أ عمدًا**: تسجيل دخول للعملاء · رفع/تحميل مستندات · أي مسار كتابة · تعديل بيانات · إشعارات خارجية (SMS/واتساب آلي = ر6).

## 1) الفلسفة — نفس الأسس بلا استثناء

- **بلا حسابات — الرمز هو الهوية**: تصنيف الخارطة للر5 واضح «لا حسابات كاملة أولًا». العميل لا يسجل دخول ولا يملك مستخدمًا — رمز عشوائي عالي الإنتروبيا يفتح نافذة قراءة محصورة. أي مستخدم/كلمة مرور للعملاء يوسّع السطح الأمني ويصنع كيانًا موازيًا للمستخدمين (مرفوض).
- **هاش حصرًا — النص الصريح مرة واحدة**: الرمز يُخزَّن **SHA-256 هاشًا**؛ النص الصريح يُعرض في حوار واحد لحظة الإنشاء (مع زر نسخ وتحذير «لن يظهر مرة أخرى») ولا يُخزن إطلاقًا. تسريب نسخة احتياطية كاملة للقاعدة **لا يكشف** أي رابط حي.
- **قراءة فقط ومحتوى محصور من الصف نفسه**: الرمز مرتبط بـ`customerId` في صفه — يفتح كشف ذلك العميل حصرًا عبر نفس `buildCustomerStatement` القائمة حرفيًا. لا استعلام عما سوى عميله، ولا مسار كتابة واحد.
- **لا رابط حي بلا نهاية**: صلاحية محدودة تُحكم خادميًا عند كل طلب + إبطال يدوي فوري من ملف العميل. (انتهاء تلقائي بمقارنة خادمية — المشروع بلا cron، لا مهمة مجدولة).
- **لا عدادات مشتقة** (درس G9): تتبع الاستخدام بحقلَي `lastUsedAt/lastUsedIp` على صف الرمز — **لا جدول زيارات ولا عداد مشاهدات**.
- **حد طلبات في الذاكرة المحلية**: سياسة المشروع ذاكرة محلية بلا Redis — حد أساسي (د6) كخط دفاع ثانٍ؛ الدفاع الفعلي هو إنتروبيا الرمز (256-bit). الصدق الهندسي: على Vercel serverless الذاكرة لكل lambda — الحد تشتيت لا جدار، ونعرفه ونذكره في البطاقة.
- **النواة النقية أولًا** (نمط consulting-v1/opportunities): توليد الرمز وهاشه وحكم الصلاحية والإبطال ورسائل الرفض العربية — دوال نقية في `portal-core.ts` + اختبارات bun قبل أي ربط.

## 2) قرارات تحتاج اعتمادك (القيم الافتراضية المقترحة — تُعدل عند الاعتماد)

| # | القرار | المقترح | البديل |
|---|--------|---------|--------|
| د1 | الرمز وتخزينه | `crypto.randomBytes(32)` → base64url (43 محرفًا) — يُخزَّن **SHA-256 hex هاشًا** في `tokenHash` فريد؛ الصريح يُعرض مرة واحدة عند الإنشاء | تخزين صريح (تسريب كامل عند أي فتحية — مرفوض) أو ترميز ذاتي الفحص JWT (وزن وبلا إبطال فوري — مرفوض) |
| د2 | الصلاحية | اختيار عند الإنشاء: **30 · 90 · 365 يومًا — الافتراضي 90**؛ الحكم مقارنة `expiresAt` خادمية بلا cron | دائم بلا انتهاء (أعلى بند مخاطرة في الخارطة — مرفوض) أو أسبوعي (يتجدد كل أسبوع = عبء موظف) |
| د3 | الإبطال والسجل | قائمة روابط العميل في تبويب «الكشف المالي»: شارة الحالة (نشط/منتهي/مبطول) + الإنشاء + الانتهاء + آخر استخدام — وزر **«إبطال»** يضبط `revokedAt` فورًا | حذف الصف (يفقد سجل الإصدار — الإبطال يحقق الغرض ويُبقي التاريخ) |
| د4 | المسار العام | `GET /api/portal/statement/[token]` — **بلا `authGuard`** (الحرس لكل مسار في هذا المشروع، لا middleware عام) يتحقق هاشًا ثم انتهاءً ثم إبطالًا ثم حد الطلبات، ويعيد PDF عبر خط الأنابيب القائم حرفيًا؛ الرمز الخاطئ → **404 عام** بلا تمييز (لا حصر للأسباب) | صفحة بوابة كاملة الآن (مرحلة ب بأمر المالك) |
| د5 | محتوى الكشف | **نفس كشف ر2 حرفيًا بلا أي تعديل على التخطيط** — `buildCustomerStatement` + `buildCustomerStatementHtml` + `renderHtmlToPdf` كما هي، بنفس الفلاتر الافتراضية (كل العقود، بلا حدود فترة) | تخطيط مخصص مختلف (مضاعفة محرك عرض على كشف واحد — مخالف للفلسفة) |
| د6 | حد الطلبات | في الذاكرة: **60 طلبًا/ساعة لكل رمز** و**10 محاولات فاشلة/ساعة لكل IP** → 429 برسالة عربية (نافذة انزلاقية بسيطة `Map`) | بلا حد (مرفوض) أو Redis/قاعدة عدادات (سياسة المشروع: ذاكرة محلية — وعدم العدادات مشتقة G9) |
| د7 | تتبع الاستخدام | `lastUsedAt` + `lastUsedIp` على صف الرمز عند كل استدعاء ناجح — بلا جدول زيارات ولا عداد (G9) | سجل زيارات كامل (جداول وحمل بلا قيمة قرار — مرفوض) |
| د8 | موضع الإصدار والواجهة | زر **«رابط كشف مؤقت»** في تبويب **«الكشف المالي»** بملف العميل (ر2) — بجانب زر PDF الحالي؛ الحوار: المدة → يعرض الرابط مرة واحدة + نسخ | قائمة منفصلة خارج ملف العميل (تجزئة مسار واحد) |
| د9 | حذف العميل | صفوف الرموز تُحذف **Cascade** مع العميل (علاقة `onDelete: Cascade`) — والرموز المنتهية/المبطولة للعملاء الباقين تبقى صفوفًا تاريخية | تنظيف مجدول (لا cron في المشروع) |
| د10 | التسجيلات | `TENANT_MODELS` + `BACKUP_MODELS` للجدول الجديد + **audit للإصدار والإبطال** — **لا موديول جديد بالكتالوج ولا بلاطة** (الرابط جزء من ملف العميل القائم — لا شاشة جديدة للفريق) | موديول «بوابة» مستقل (لا بلاطات ولا شاشات جديدة تبرره — مرفوض) |

**ملاحظة أمنية صريحة (مقبولة بالتصميم)**: الرمز ينتقل في عنوان URL — يظهر في سجلات الوسطاء. هذا ثمن المشاركة عبر واتساب/SMS الذي هو الغرض ذاته. التخفيف المعتمد: إنتروبيا 256-bit (تخمين عمليًا مستحيل) + صلاحية قصيرة قابلة للاختيار + إبطال فوري + رؤية آخر استخدام للمالك + `X-Robots-Tag: noindex` على المسار العام + TLS في الإنتاج. البديل الوحيد الأصلح (رمز بخوارزمية توقيع ذي إبطال) أثقل بلا قيمة إضافية هنا.

## 3) المخطط (Prisma) — جدول واحد جديد لا غير

```prisma
// ر5 — بوابة العميل: رموز وصول مؤقتة لكشف PDF (docs/customer-portal-design.md)
// الرمز الصريح لا يُخزن إطلاقًا — هاش SHA-256 حصرًا (د1) · قراءة فقط بلا أي مسار كتابة (§1)
model CustomerPortalToken {
  companyId  Int      @default(1) @map("company_id")
  id         Int      @id @default(autoincrement())
  customerId Int      @map("customer_id")
  customer   Customer @relation("CustomerPortalToken", fields: [customerId], references: [id], onDelete: Cascade) // د9
  tokenHash  String   @unique @map("token_hash")            // sha256 hex — د1
  expiresAt  DateTime @map("expires_at")                    // د2 — الحكم خادمي بلا cron
  revokedAt  DateTime? @map("revoked_at")                   // د3 — إبطال يدوي فوري
  lastUsedAt DateTime? @map("last_used_at")                 // د7 — لا عدادات (G9)
  lastUsedIp String   @default("") @map("last_used_ip")
  createdBy  Int?     @map("created_by")
  createdAt  DateTime @default(now())

  @@index([customerId])
  @@map("customer_portal_tokens")
}
```

+ سطر علاقة واحد في `Customer`: `portalTokens CustomerPortalToken[] @relation("CustomerPortalToken")`.
بلا ترقيم ذري (الرمز ليس مستندًا مرقمًا — لا `nextNumberByKey`)، وبلا enum، وبلا جدول مرافق.

## 4) النواة النقية — `portal-core.ts` + `portal-constants.ts`

- `PORTAL_LINK_CHOICES = [30, 90, 365]` + `PORTAL_DEFAULT_DAYS = 90` (د2).
- `generatePortalToken(): { token: string; tokenHash: string }` — `randomBytes(32)` base64url + sha256 hex.
- `hashPortalToken(token: string): string` — حتمي للتحقق عند كل طلب.
- `validatePortalTokenRow(row, now): { ok: true } | { ok: false; generic: true }` — منتهي/مبطول/لا صالح → **رفض عام موحد** (د4: لا تمييز الأسباب للطرف العام)؛ رسائل السبب العربية الدقيقة للمسار الداخلي والسجل فقط.
- `portalRatePolicy` — ثوابت د6 (60/ساعة للرمز · 10 فاشلة/ساعة لكل IP) + `checkRateWindow(count, limit)` نقي.
- اختبارات bun: توليد بطول ثابت وإنتروبيا · هاش حتمي ومستقر · انتهاء بالتاريخ · إبطال بعد النجاح · الرمز الخاطئ رفض عام · حدود النافذة — قبل أي ربط مسار أو واجهة.

## 5) المسارات (API)

| المسار | الحرس | الغرض |
|---|---|---|
| `POST /api/customers/[id]/portal-links` | `authGuard(req, "screen_customers")` | إنشاء رابط (`days` من د2) — يعيد **الرابط الصريح مرة واحدة** + صف الحالة؛ audit إصدار |
| `GET /api/customers/[id]/portal-links` | `authGuard(req, "screen_customers")` | قائمة الروابط (بلا صريح أبدًا): الحالة/الإنشاء/الانتهاء/آخر استخدام |
| `DELETE /api/customers/[id]/portal-links/[tokenId]` | `authGuard(req, "screen_customers")` | إبطال فوري (`revokedAt`) — audit إبطال |
| `GET /api/portal/statement/[token]` | **عام — بلا حرس** (د4) | تحقق هاش+انتهاء+إبطال+حد → PDF الكشف بنفس خط الأنابيب؛ تحديث `lastUsedAt/Ip` عند النجاح؛ `X-Robots-Tag: noindex` |

عزل الشركة: `companyId` من صف الرمز نفسه لا من الجلسة (لا جلسة أصلًا) — و`buildCustomerStatement` تُنادى بمعرف العميل من صف الرمز حصرًا.

## 6) الواجهة — ملف العميل القائم لا شاشة جديدة

- تبويب **«الكشف المالي»** في `CustomerFilePage` (ر2): بطاقة **«بوابة العميل — روابط كشف مؤقتة»** تحت أزرار الكشف الحالية:
  - زر **«إنشاء رابط»** → حوار: مدة (30/90/365) → ينشئ ويعرض الرابط الصريح **مرة واحدة** + زر نسخ + تنبيه «احفظه الآن — لن يظهر مرة أخرى».
  - قائمة الروابط: شارة الحالة (نشط/منتهي/مبطول بألوان الهوية) + تاريخ الإنشاء + الانتهاء + آخر استخدام + زر **«إبطال»** بتأكيد.
- هوية NOVA (بلا ألوان خارج اللوحة) · RTL · موبايل 390 · شريط سفلي مثبت (`min-h-screen flex flex-col + mt-auto`).
- صفر تعديل على مسارات الفريق الأخرى — لا بلاطة ولا قائمة جانبية جديدة.

## 7) المرحلة ب — مسودة مبدئية بلا تنفيذ (بأمر المالك حصرًا)

- `GET /portal/[token]` صفحة HTML عامة RTL بهوية NOVA: مؤشرات أعلى (قيمة العقود النشطة · المستحق المستحق غير المسدد · آخر دفعة) + جدول الدفعات المستحقة (`payment_plan` بتواريخ الاستحقاق الفعلية) + زر تحميل كشف PDF (المسار العام نفسه) — قراءة فقط بنفس تحقق الرمز وحدود الطلبات.
- تنبيه مالك الحقيقة: كل عرض جديد يوسّع السطح — قرارات المحتوى الدقيقة تُعرض في بطاقة تحديث حين طلبها المالك، لا قبل.

## 8) الاختبارات والتحقق قبل الدفع

1. **نواة**: bun tests خضراء (توليد/هاش/انتهاء/إبطال/رفض عام/حدود نافذة).
2. **تحقق حي متصفحي**: إنشاء رابط من ملف العميل → نسخه → فتحه في سياق **غير مسجل** (خروج) → PDF يعمل → إبطال من الملف → الرابط يعيد 404 عربي عام → محاكاة انتهاء → 404 → حد الطلبات → 429 → فحص 390 موبايل → صفر أخطاء كونسول.
3. **lint صفر** + التسجيلات الأربع (TENANT/BACKUP/audit) + إلحاق DEVLOG/PROJECT-LOG → عندها فقط دفع main = نشر إنتاج.

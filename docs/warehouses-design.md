## 1) الفلسفة — نفس الأسس بلا استثناء

- **خط واحد للمالية**: كل قيمة تدخل الأستاذ عبر `postJournalEntry` حصرًا (نمط payroll/eos) — المستند المخزني المحفوظ **يقيد فورًا** (مبدأ خطة النواة: «المستند بلا قيد = مسودة» ولا مسودات في المخازن). لا قواعد ترحيل جديدة ولا مسار كتابة ثانٍ.
- **الأرصدة اشتقاقية لا مخزنة (جوهر الموديول — درس G9 المحقق)**: لا جدول أرصدة ولا عدادات تتقدم — الرصيد والقيمة والمتوسط المرجح **دالة نقية من الأسطر** تُحسب لحظة السؤال. «أداة إعادة الاحتساب» التي ندّعوها في NovaFlow هي البنية نفسها: لا شيء يُخزَّن أصلًا.
- **اللقطات المجمّدة (Cost Snapping)**: سطر الإذن يجفّف `snapUnitCost` و`amount` لحظة الحفظ — لا تُقرأ تكلفة الصرف من حسابات لاحقة أبدًا.
- **المعرفية لا النصية (G7)**: الأنواع قيم معرفية بجداول ثابتة (`entry|issue|transfer|count`)، وكل ربط بمفاتيح أجنبية حقيقية — إعادة تسمية أي طرف لا تكسر شيئًا.
- **النواة النقية أولًا** (consulting-v1): كل الحسابات (توازن الحركة، المتوسط المرجح، فحص السالب، فروق الجرد، انحراف البنود) دوال نقية في `warehouses-core.ts` + اختبارات bun قبل أي ربط.
- **جدولان لا أربعة**: رأس إذن واحد + أسطره تخدم الأنواع الأربعة كلها (نمط Voucher/JournalLine) — درس G3/G5: لا جدول بلا استخدام ولا تكرار بنيوي.

## 2) قرارات تحتاج اعتمادك (القيم الافتراضية المقترحة — تُعدل عند الاعتماد)

| # | القرار | المقترح | البديل |
|---|--------|---------|--------|
| د1 | الدورة المحاسبية للمخزون | **دورة كاملة بقيدَين حقيقيين**: الإدخال (مدين مخزون ↔ دائن نقد/مورد) والصرف (مدين مواد ببُعد العقد ↔ دائن مخزون) — المخزون أصل في الميزانية وتكلفة المواد تدخل القوائم من بوابة الكتالوج | طبقة تحليلية بلا قيد (يبقى المخزون خارج الدفاتر ويُقيّد الشراء مصروفًا عند الدفع — لا خصم عند الصرف) |
| د2 | طريقة التكلفة | **متوسط مرجح اشتقاقي**: القيمة = Σ داخل − Σ خارج (بأسطرها المجففة)، الكمية مثلها، المتوسط = القيمة ÷ الكمية — ولقطة `snapUnitCost` على كل سطر صرف/جرد | FIFO بدفاتر (بنية تتبع دفعات كاملة — تأجيل معلن) |
| د3 | بنية المستندات | **جدولان فقط**: `StockDoc` رأس + `StockDocLine` أسطر تخدم الأنواع الأربعة (إدخال·صرف·تحويل·جرد) | جدول لكل نوع (تكرار 4× وأعمدة ميتة) |
| د4 | الرصيد السالب | **منع**: صرف أو نقص جرد يتجاوز الرصيد الاشتقاقي لحظة تاريخ الإذن ⇒ رفض برسالة عربية تسمّي الصنف والمستودع والمتاح (نمط د7 HR-3) | سماح مع تحذير (قسمة سالبة تفسد المتوسط المرجح) |
| د5 | الترقيم | بادئات لكل نوع عبر `nextNumber` لكل شركة: `WI-`إدخال · `WO-`صرف · `WT-`تحويل · `WC-`جرد (نمط RV/PV/TV/CV/SD) | تسلسل موحد بلا بادئات |
| د6 | الحالة والتعديل | حفظ ⇒ **مرحّل بقيد فوري** (لا مسودة)؛ الإلغاء ⇒ قيد عكسي مرتبط + سبب؛ **التعديل ممنوع بعد الحفظ** — إلغاء وإعادة إنشاء (نمط السندات حرفيًا) | مسودات وتعديل (يفقد «المستند بلا قيد» معناه) |
| د7 | ربط العقود | الصرف/المرتجع على **عقد واحد برأس الإذن**، وسطر الإذن يُربط اختياريًا بـ**بند BOQ** (`boqItemId`) — يفتح تقرير **انحراف المواد على البنود**: التعاقدي مقابل المنصرف | `contractId` لكل سطر (مرونة نادرة الحاجة تعقد الحوارات) |
| د8 | الربحية | عمود **«تكلفة المواد (المخازن)»** من الأسطر المجففة (صرف − مرتجع موقع، أذون posted حصرًا) و**«الربح الشامل» = المنصرف النقدي − العمالة − المواد** — المعادلات النقدية بلا أي مساس (نفس ثلاث نقاط HR-3) | دمج المواد في «المنصرف» (يشوّه النقد ويكرر السندات المباشرة) |
| د9 | حسابات المخازن | **بذر مؤجل بنمط HR** (`ensureWarehouseAccounts` بنمط `ensureOne` في hr-server): `1160 «مخزون المواد»` (أصل، شقيق 1150) + `5115 «فروق الجرد والهدر»` (مصروف، شقيق 5110) عند أول قيد — الشجرة الافتراضية لا تُمس وبذر HR-2 السابق يُحتذى | إضافة للشجرة الافتراضية (حسابات ميتة لشركات لا تفعّل المخازن — G3) |
| د10 | الجرد | إذن جرد بمستودع واحد يُدخل **الكمية المفحوصة** ⇒ الفروق تُحتسب آليًا وتقيّد قيمتها بسعر اللقطة الحالي: نقص مدين 5115/دائن مخزون، زيادة بعكسها — التاريخ لا يُعدل | تعديل الأسطر التاريخية (يفقد الأثر التدقيقي) |
| د11 | أطراف الإدخال | المورد **نص حر** على رأس الإذن + مصدر معرفي (`cash|credit|return`): نقدي يختار حساب دفع (صندوق/بنك) · آجل يقيد دائن **2111 الموردون** بوصف يذكر الاسم · مرتجع موقع يقيّد دائن 5110 ببُعد العقد | كيان مورد كامل الآن (جدول بلا استخدام قبل موديول المشتريات — G3/G5؛ يأتي لاحقًا) |
| د12 | الصلاحيات | مفتاح واحد `screen_warehouses` (نمط `screen_hr`) + `moduleGuard("warehouses")` على كل مسارات `api/warehouses/*` — بلا تفصيل أدوار في v1 | أدوار (أمين مخزن/مراقب) — تأجيل معلن |

## 3) المخطط (Prisma) — 4 جداول جديدة (كلها companyId + تُضاف إلى TENANT_MODELS/BACKUP_MODELS بنفس الـcommit — درس T111)

```prisma
model Warehouse {                    // د — المستودعات: بيانات أساسية خفيفة
  name String                       // @@unique([companyId, name])
  location String @default("")
  active Boolean @default(true)     // التعطيل يخفيه من الأذون الجديدة؛ ذو حركة لا يُحذف
  notes String @default("")
  @@map("warehouses")
}

model StockItem {                    // الصنف — التسمية StockItem لتفادي التصادم مع BoqItem الموجود
  name String                       // @@unique([companyId, name])
  unit String @default("")          // وحدة قياس نصية للعرض (كيس/م/م²/كجم…) — بلا تحويلات وحدات
  category String @default("")
  minQty Decimal @default(0) @db.Decimal(18,3)  // حد تنبيه عرض فقط (شارة تحت الحد الأدنى)
  active Boolean @default(true)     // ذو حركة لا يُحذف — تعطيل فقط
  notes String @default("")
  @@map("stock_items")
}

model StockDoc {                     // رأس الإذن — الأنواع الأربعة جميعها (د3)
  docNumber String                  // WI/WO/WT/WC-#### (د5) — @@unique([companyId, docNumber])
  kind String                       // entry | issue | transfer | count (قيم معرفية — G7)
  entrySource String @default("")   // entry فقط: cash | credit | return (د11)
  vdate String                      // YYYY-MM-DD
  warehouseId Int  (Cascade)        // المستودع (في التحويل: المصدر) — علاقتان مسمّتان Warehouse↔StockDoc
  targetWarehouseId Int? (Cascade)  // التحويل: المستودع المستهدف (≠ المصدر)
  contractId Int?  (Cascade)        // الصرف/المرتجع على عقد واحد إلزاميًا لهما (د7/د8 — G8)
  party String @default("")         // اسم المورد نص حر (د11)
  payAccountId Int?                 // الإدخال النقدي: حساب الصندوق/البنك المختار
  payAccountName String @default("")// لقطة اسم حساب الدفع
  journalEntryId Int?               // FK → JournalEntry — القيد المرتبط يعرض بالتفاصيل (نمط السندات)
  status String @default("posted")  // posted | cancelled — لا مسودات (د6)
  cancelReason String @default("")
  cancelledAt DateTime?
  notes String @default("")
  createdBy String @default("")
  @@index([companyId, kind]) @@index([warehouseId]) @@index([contractId]) @@index([vdate])
  @@map("stock_docs")
}

model StockDocLine {                 // السطر — اللقطات هنا
  docId Int   (Cascade)
  itemId Int   (Cascade)
  boqItemId Int?                    // ربط بند الكميات التعاقدية — تقرير الانحراف (د7، G1)
  qty Decimal @db.Decimal(18,3)     // الجرد: الفرق المقيّد (±) — الأنواع الأخرى موجبة
  countedQty Decimal @default(0) @db.Decimal(18,3)  // الجرد: المفحوص (توثيق فقط)
  snapUnitCost Decimal @db.Decimal(18,3)  // لقطة التكلفة لحظة الحفظ (د2)
  amount Decimal @db.Decimal(18,3)  // = qty × snapUnitCost مجمّد
  note String @default("")
  @@index([docId]) @@index([itemId]) @@index([boqItemId])
  @@map("stock_doc_lines")
}
// علاقات عكسية: Contract.stockDocs · JournalEntry.stockDocs · BoqItem.stockDocLines · Warehouse/StockItem عكساتها
```

## 4) قواعد الحركة والتكلفة (النواة النقية `warehouses-constants.ts` + `warehouses-core.ts`)

- **الحركة الموحدة**: كل سطر يُترجم إلى حركة `(صنف، مستودع، تاريخ، كمية±، قيمة±)` — الإدخال/المرتجع داخل موجب، الصرف داخل سالب، التحويل **زوج** (خروج بالمصدر بكمية وقيمة اللقطة + دخول بالمستهدف بنفسهما)، الجرد ± بالفرق.
- **الأرصدة الاشتقاقية** (`computeBalances`): لكل صنف×مستودع — `qty = Σداخل − Σخارج`، `value = Σقيم داخل − Σقيم خارج` (أسطر مجففة)، `wac = qty > 0 ? value ÷ qty : 0` — من أذون `posted` حصرًا؛ **الملغاة شفافة** وعكسها آلي بمجرد الإلغاء.
- **منع السالب** (`validateAvailability`): مجموع حركة الصنف داخل المستودع **حتى تاريخ الإذن** يجب ألا يجعل الرصيد سالبًا — وإلا رفض برسالة عربية تسمّي الصنف والمستودع والرصيد المتاح (د4).
- **تحقق المستند** (`validateStockDoc`): كمية > 0 للإدخال/الصرف/التحويل؛ جرد بـ`countedQty ≥ 0`؛ لا صنف مكرر بالإذن؛ الصنف والمستودعات نشطة؛ **الصرف بلا عقد مرفوض، المرتجع بلا عقد مرفوض، التحويل بلا مستهدف أو بمستهدف = مصدر مرفوض** (G8 الإلزامية)؛ `boqItemId` يجب أن يعود لعقد رأس الإذن.
- **لقطات الحفظ**: سعر الصرف/الجرد الافتراضي في الواجهة = متوسط الصنف الحالي (وآخر سعر صرف عند المرتجع) — لكن المصدر النهائي ما يجفّفه السطر؛ `amount = r3(qty × snapUnitCost)` مجمّد.
- **فروق الجرد** (`computeCountDeltas`): فرق = مفحوص − رصيد الاشتقاقي لحظة التاريخ؛ الفرق يُقيّد بسعر اللقطة الحالي (د10).
- **انحراف البنود** (`deviationOfBoq`): لكل بند BOQ بالعقد — الكمية/القيمة التعاقدية مقابل المنصرف من المخازن (Σ أسطر الصرف المربوطة به − مرتجعاته) + الفرق الملوّن — **تحليل انحراف المواد على FK حقيقي، النقيض الحرفي لفجوة G1**.
- **تكلفة عقد** (`materialsCostOfContract`): `Σ أسطر صرف على العقد − Σ أسطر مرتجع موقع إليه` من أذون posted — هذه الوظيفة وحدها تقرأها الربحية والنظرة (لا حسابات موازية).

## 5) التكامل المحاسبي (د1/د9 — كل القيود عبر `postJournalEntry` داخل معاملة واحدة مع المستند وأسطره، نمط payroll approve)

| الإذن | القيد | sourceType |
|---|---|---|
| إدخال نقدي | مدين **1160 مخزون المواد** ↔ دائن حساب الدفع المختار (صندوق/بنك) | `inventory_entry` |
| إدخال آجل | مدين **1160** ↔ دائن **2111 الموردون** (وصف يذكر المورد نصًا) | `inventory_entry` |
| إدخال مرتجع موقع | مدين **1160** ↔ دائن **5110 مواد وأدوات** بسطر بُعد `contractId` — يخفض تكلفة المواد على العقد | `inventory_entry` |
| صرف | مدين **5110** بسطر بُعد `contractId` (+ `boqItemId` عند الربط) ↔ دائن **1160** | `inventory_issue` |
| تحويل | **بلا قيد** — نقل موقع لا قيمة (أصل واحد داخل الشركة) | — |
| جرد (نقص/زيادة) | فرق القيمة: مدين **5115 فروق الجرد والهدر** ↔ دائن 1160، والزيادة بعكسها | `inventory_count` |
| إلغاء | قيد عكسي مرتبط `reversalOfId` (نمط السندات) | `reversal` |

- **بذر مؤجل** (`ensureWarehouseAccounts` بنمط `ensureOne` في hr-server.ts): يبذر 1160 و5115 كأوراق شقيقة عند أول قيد إن غابا — الشجرة الافتراضية لا تُمس (د9).
- **قاعدة عدم الازدواج (معلنة ومنفّذة)**: المشتريات **المختزنة** تمر بإذن الإدخال (أصل)، والمشتريات **المستهلكة فورًا** تمر بسند صرف مباشر على 5110 كما اليوم — مساران معلنان لا يتقاطعان؛ قيود أذون المخازن ليست سندات فلن تُحتسب في «المنصرف النقدي» بالربحية، فلا ازدواج ولا فجوة.
- **السداد البنكي الكبير للمشتريات**: يبقى عبر المسار القائم (آجل ⇐ سند PV للمورد لاحقًا) — أذون المخازن لا تتكامل مع البوابة البنكية عمدًا (حدود §10).

## 6) تكلفة المواد في تقارير العقود (د8 — امتداد HR-3 بالنقاط الثلاث نفسها)

- **تقرير الربحية** (`api/reports/profitability`): استعلام رابع — أسطر الأذون `posted` مجمّعة بالعقد عبر `materialsCostOfContract` ⇒ عمود `materialsCost` + تحديث «الربح الشامل» = `actualProfit − laborCost − materialsCost` + المجاميع والملاحظة.
- **نظرة العقد** (`api/contracts/[id]/overview`): سطر «تكلفة المواد من المخازن» + قائمة آخر أذون الصرف/المرتجع بتواريخها ومبالغها.
- **تقرير انحراف المواد على بنود العقد**: داخل قسم «الأرصدة والتقارير» بمخازن (منتقي عقد) — بلا إدخال جديد في reports-list (نمط HR-3: سطح أصغر، والمصدر مبدأ حساب واحد).
- الموالف النقدية المباشرة (سندات على 5110) تبقى في «المنصرف» كما هي — العمودان الجديدان للمخزون حصرًا.

## 7) الواجهة والشل والصلاحيات

- **الشل**: `ModuleId` يزداد `"warehouses"` + كتلة NAV_MODULES بند «المخازن» (Package) بعد الموارد البشرية وقبل المحاسبة، بثلاثة بنود كلها `view: "warehouses"`:
  1. **«الأصناف والمستودعات»** — `section: "items"` — بطاقتان بنمط HR: المستودعات (اسم/موقع/ملاحظة/تعطيل) والأصناف (اسم/وحدة/فئة/حد أدنى/ملاحظة/تعطيل) — الحذف الفيزيائي ممنوع لمن له حركة برسالة عربية، والتعطيل هو البديل.
  2. **«أذون المخازن»** — `section: "docs"` — فلاتر (نوع/مستودع/حالة/فترة) + أربعة أزرار إنشاء + حوار تفاصيل بالأسطر والقيد المرتبط (رقم القيد + فتحه — نمط السندات) + إلغاء بسبب للمدير؛ المستند المرحّل غير قابل للتعديل (د6). حوارات الإنشاء الأربعة: إدخال (مصدر/مورد/حساب دفع + شبكة أسطر بالسعر الافتراضي)، صرف (منتقي عقد + ربط بنود BOQ اختياريًا + «الرصيد المتاح» تحت كل صنف)، تحويل (مستودعان + أسطر)، جرد (جدول مفحوص/مسجَّل/الفرق آليًا).
  3. **«الأرصدة والتقارير»** — `section: "balances"` — مصفوفة أرصدة (صنف × مستودع) بقيمة ومتوسط مرجح + شارة «تحت الحد الأدنى» + كشف حركة صنف (حوار بكل الحركات المجمفة) + منتقي عقد لتقرير انحراف البنود.
- **KPI أعلى الشاشة** (بنمط HRView): قيمة المخزون · عدد الأصناف النشطة · أصناف تحت الحد الأدنى · أذون هذا الشهر.
- **الصلاحيات**: `VIEW_PERMS["warehouses"] = "screen_warehouses"` + مفتاح في PERMISSIONS (الشاشات، `secretary: true`) + `moduleGuard(companyId, "warehouses", "المخازن")` بعد `authGuard` في كل المسارات — إخفاء الشل تلقائيًا عبر `navModulesFor` عند الإيقاف.
- **الكتالوج**: بنفس commit التنفيذ — `available: true` + `navModules: ["warehouses"]`؛ قسم `div-warehouses` يُبذر آليًا عند التفعيل (`ensureModuleDivision` القائم).
- **audit** على كل حركة (`stock_doc`/`warehouse`/`stock_item`) — نمط HR حرفيًا.

## 10) حدود الموديول (ما لا يُبنى عمدًا)

- بلا أوامر شراء/طلبات موردين — الإدخال مباشر، وموديول المشتريات يأتي مع المبيعات لاحقًا (وعندها كيان المورد يستقر ويُربط) ·
- بلا استيراد CSV للأصناف (إدخال يدوي — يُقرر عند الحاجة) · بلا تحويل وحدات (الوحدة نص للعرض) · بلا FIFO/دفعات/صلاحية (متوسط مرجح اشتقاقي فقط — د2) ·
- بلا باركود/سكانر · بلا حجز كميات (reservations) · بلا صرف لعمالة/معدات أو عهدة مواد للموظفين (المخزون مواد فقط؛ عهدة السلف القائمة لا تُمس) ·
- بلا إشعارات آلية للحد الأدنى (شارة عرض فقط — الإشعارات حدّ HR-2 باقٍ) · بلا دورات جرد مجدولة (جرد عند الطلب) ·

- بلا تكلفة على مستوى مرحلة العقد (بُعد العقد وبند BOQ فقط) · بلا تعدد عملات (د.ك ثلاثي العشرة) · بلا تصدير XLSX جديد (طباعة المتصفح تكفي) ·

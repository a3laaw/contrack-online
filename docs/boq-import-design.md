## 1) تشريح الملف الحقيقي

### 1.1 الأوراق (23)

| النوع | الأوراق | الدور |
|---|---|---|
| غلاف/فهرس | `Div1` (BILLS OF QUANTITIES + اسم المشروع)، `Index` | فهرس الأقسام بأرقام الصفحات |
| أقسام الأعمال | `Div. 1`، `Div2`…`Div 32`، `Mech Div. 21/22`، `HVAC Div. 23-`، `ELEC-Div.26-28` | البنود المسعّرة — قلب الاستيراد |
| تعديلات المزايد | `TENDERERS ADJ SCHE` | فروق حساب المزايد (تُتخطى في v1) |
| الملخص العام | `Summary` (GENERAL SUMMARY) | إجماليات الأقسام + القيمة الإجمالية — **أداة تحقق** |
| شهادة دفع | `PYT- cert` (PAYMENT CERTIFICATE No. 05) | مستخلص — **ليست جزءاً من الاستيراد** (نطاق المرحلة أ) |

مشروع المثال: مستوصف صباح السالم الجنوبي — مالك وزارة الصحة، الاستشاري سور، المقاول شركة صناعات أنظمة البناء. القيمة بعد التعديل **980,000 د.ك** (الأصلية 1,020,037 قبل تعديل المزايد −40,037).

### 1.2 بنية قسم أعمال (POMI الإنجليزية الكويتية)

**رأس التسعير** (يتكرر مع كل صفحة داخل نفس الورقة — نمط «صفحات» المطبوعة):

```
Item No. | Description | Qty. | Unit | Unit Price (K.D.) | Total Price (K.D.)
[| PERVIOUS | CURRENT | Total percentage | Total Price (K.D.)]
```

- مرادفات فعلية في الملف: `ITEM`/`Item No.`/`No.` · `QTY`/`Qty.`/`Qty` · `UNIT RATE`/`Unit Price (K.D.)`/`Unit Rate (K.D.)` · `AMOUNT`/`Total Price (K.D.)`/`Total Amount (K.D.)`.
- الأعمدة الإضافية G-J (PERVIOUS/CURRENT/نسبة/قيمة) = حالة استرداد المستخلصات — **تُتجاهل عند الاستيراد** (سحب بنود العقد فقط).
- **أعمدة المزايددين المتعددين:** ورقة `Div1` تحمل حتى 4 أزواج (Unit Price, Total Price) لأربعة مزايددين — يُؤخذ **الزوج الأول** حصراً.

**صيغ ترقيم البنود (نمطان):**
1. **مدني:** `03.30.01` = قسم.مجموعة.تسلسل (Regex: `^\d{1,2}\.\d{2}\.\d{1,3}$`).
2. **ميكانيكي/كهربائي:** أحرف أقسام `A`, `B1`, `C`… وبنود بأعداد صحيحة تعيد الترقيم داخل القسم → الهوية المركّبة `B1-2`.

**صفوف يجب تمييزها (والتي تُتخطى):**
- `TOTAL CARRIED TO COLLECTION` — إجمالي الصفحة (علامة نهاية صفحة تسعير).
- رأس **COLLECTION** (`No. | Description | Amount KD` بلا Qty/Unit) ثم صفوف مرجعية `Div-3-1` — تجميع صفحات القسم.
- `Divison 3 SUMMARY` — ملخص القسم.
- **سطور الشروح/المواصفات:** وصف بلا رقم بند ولا كمية ولا سعر (مثل فقرات مواصفات الخرسانة وملاحظات MEW) — تُحصى وتُتخطى في v1 (الملف الأصلي يبقى مرجع المواصفات).
- بنود غير مسعّرة: السعر `INCLUDED` (مشمول) أو فارغ مع وحدة `L.S` — **تُستورد بسعر 0** (بنود تعاقدية بلا قيمة، ومطابقة لملخص Summary الذي يظهر أقساماً بقيمة 0).

**وحدات القياس الفعلية:** `L.S.`/`LS` (مقطوعية)، `M2`/`M²`، `M3`/`M³`، `LM` (متر طولي)، `Nos.`/`No's`/`Nos`/`NO`/`No` (عدد)، `Item`/`ITEM`، `m`، `M.R` — تُستورد كما وردت حرفياً.

### 1.3 سلسلة الحساب (الصيغ الحرفية من الملف)

```
بند:      F = C×E (الإجمالي = الكمية×سعر الوحدة)
          I = G+H (النسبة الكلية = سابق+حالي)   J = I×F
صفحة:     F_page = ΣF · Y=Σ(G×F) · Z=Σ(H×F) · G_page=Y/F (نسبة مرجحة بالقيمة)
ملخص:     D_summary = رابط لخلية ملخص القسم · الإجمالي = Σ الأقسام + بنود مؤقتة
شهادة:    A = الأعمال المنفذة · خصم 10% محتجزات + استرداد 10% دفعة مقدمة
```

**شهادة الدفع (`PYT- cert`) تؤكد نطاق المرحلة أ المُنفَّذ:** Original/Adjusted Contract Sum · VO إضافات/حذوفات · (A) قيمة الأعمال + 80% مواد بالموقع · (B) خصومات: **10% Retention + Recovery of Advance Payment** + أخرى · الصافي A-B − المستخلصات السابقة (P.C. No.1…) = **NET AMOUNT DUE**. النظام الحالي يغطي هذا كاملاً (1122 محتجزات + لقطة استرداد الدفعة).

### 1.4 الملخص العام (`Summary`) — أداة التحقق

صف لكل قسم: `DIVISION 3: CONCRETE | Amount KD. Bills | نسب سابقة/حالية/كلية | قيم`. ثم:
`PROVISIONAL ITEMS (40,000)` → `GROSS TOTAL PRICE (1,020,037)` → بعد التعديل `980,000` → المستحق التراكمي والصافي.
**قاعدة التحقق عند الاستيراد:** مجموع بنود القسم المستورد ≈ خانة Amount KD للقسم (تفاوت ≤ 0.05% أو ≤ 1 د.ك مقبول — فروق تقريب)، والفرق الجوهري يُعلن تحذيراً.

## 2) التصميم — سحب BOQ إلى بنود العقد

### 2.1 قرار النموذج (تطوير BoqItem)

إضافة ثلاثة حقول هوية إلى `BoqItem` (افتراض فارغ — لا كسر لأي مسار قائم):

| الحقل | الغرض | مثال |
|---|---|---|
| `itemNo` | رقم البند في BOQ الأصلي — مفتاح مطابقة المستخلصات لاحقاً | `03.30.01` / `B1-2` |
| `divisionCode` | رقم القسم (CSI MasterFormat) | `03` / `26` |
| `divisionName` | اسم القسم | `CONCRETE` |

- لماذا لا ContractStage لكل قسم؟ المراحل لها دور دفعات مستقل (`payPct/payKind`) — خلط الأقسام بها يفسد دلالتها. الأقسام هنا هوية تصنيفية للبند.
- الإضافة على مسار CRUD القائم: GET يُرجع الحقول، POST/PATCH يقبلانها (اختيارية).

### 2.2 المحلل النقي `src/lib/import/boq-parse.ts`

**نقية بلا db** (نمط `parse-core.ts` القائم) — قابلة للاختبار على حافظة عمل ExcelJS مباشرة:

```
parseBoqWorkbook(buffer) → BoqParseResult {
  divisions: [{ code, name, itemCount, total, items: [...] }]
  grandTotal, warnings[], meta { sheets, skippedSheets[] }
}
```

**خوارزمية الماسح الحالي لكل ورقة (stateful scanner):**
1. استخراج رقم القسم من اسم الورقة (`Div. 1`/`ELEC-Div.26-28`/`Mech Div. 22` → 1/26/22).
2. البحث عن رأس تسعير (صف يضم ≥3 من: بند/وصف/كمية/وحدة/سعر وحدة بالمرادفات §1.2) → تثبيت خرائط الأعمدة، ووضع `mode=items`. رأس Collection (بلا كمية/وحدة) → `mode=collection` (تخطٍ).
3. في وضع البنود:
   - رأس مكرر → تجاوز (صفحات متعددة داخل الورقة).
   - الوصف يحوي `TOTAL CARRIED` → تجاوز (علامة نهاية صفحة).
   - **صف بند**: (رقم بند يطابق نمط مدني/عدد صحيح/حرف قسم) وبه إشارة كمية/وحدة/سعر، **أو** سعر رقمي مع كمية/وحدة بلا رقم (بنود Section غير المرقمة المسعّرة) → تحليل C/D/E/F بتسامح: كمية غير رقمية (`Items`) → 1، سعر `INCLUDED`/فارغ → 0.
   - وصف بلا أي إشارات → سطر شرح/مواصفة: يحصى ويتخطى.
4. هوية بند MEP: قسم حرفي نشط + عدد صحيح → `B1-2`؛ مدني كما ورد.
5. أوراق تُتخطى كلياً: `Index` (تُقرأ لخريطة أسماء الأقسام فقط)، `Summary` (تُقرأ للتحقق)، `PYT- cert`، `TENDERERS ADJ`، الأوراق بلا رأس تسعير.
6. **التحقق:** مقارنة إجمالي كل قسم و الإجمالي العام بخانات Summary → تحذيرات تفصيلية؛ وإجمالي البنود المستوردة يظهر في المعاينة.

### 2.3 المسار الخادمي `POST /api/contracts/[id]/boq/import`

- FormData: `file` (.xlsx) + `mode=preview|run`.
- الحرس: `action_edit_contract` (مطابق لـCRUD بنود الكميات) + سقف حجم 15MB.
- **preview:** التحليل فقط — لا كتابة. يعيد الأقسام (عدد/إجمالي/أول 5 بنود)، التحذيرات، وعدد البنود القائمة في العقد (تحذير إلحاقي).
- **run:** إعادة التحليل ثم `createMany` داخل معاملة مع `sortOrder` متسلسل من آخر ترتيب، و`companyId` يحقنه غلاف db.ts آلياً. لا يلمس البنود القائمة (إلحاق — الحذف بيد المستخدم كما في CRUD).
- إبطال كاش boq/contract/dashboard بعد التنفيذ.

### 2.4 الواجهة (BoqTab)

- زر **«استيراد ملف BOQ»** (أيقونة Upload) بجوار «إضافة بند».
- حوار ثلاثي الخطوات: اختيار ملف → **معاينة** (بطاقة إجماليات + جدول الأقسام قابل الفتح لعينة بنود + قائمة تحذيرات) → تأكيد الاستيراد → توست + إبطال الكاش.
- عمودان جديدان في الجدول: رقم البند (numeric) وشارة القسم.
- الجوال: نفس الحوار بعرض كامل، والعمودان يظهران في بطاقة البند.

### 2.5 قرارات صريحة (v1)

1. **لا دمج للشروح في وصف البند** — تبقى الوصف موجزة قابلة للاستخدام في الفواتير/الباطن/التنفيذ؛ الملف الأصلي مرجع المواصفات. (خيار مستقبلي: تبديل دمج).
2. **PERVIOUS/CURRENT تُهمل** — سحب حالة التعاقد لا حالة الاسترداد؛ المستخلصات تُدار بنظام الفواتير الحالي.
3. **زوج المزايد الأول فقط** — قيمة العقد الموقّع.
4. **البنود غير المسعّرة تُستورد بسعر 0** (تطابق Summary حيث أقسام = 0).
5. **أوراق المتعدد أقسامها تُدمج** (`ELEC-Div.26-28` → قسم 26) في v1.
6. **إلحاق لا استبدال** للبنود القائمة — مع التحذير في المعاينة.
7. صيغ xls القديمة غير مدعومة في v1 (xlsx فقط — ExcelJS).

# لوحة قيادة المشروع — البرنامج الزمني للبنود + مؤشرات EVM (تصور المالك ونموذجه الحقيقي)

> **المصدر:** جرد المالك: «عندي برنامج زمني معروف كل بند هيخلص امتي · BOQ مسعر ليا وأنا مسعره لمقاول الباطن · تقرير يومي بأعمال بنود BOQ · سابق وحالي · تنبؤ زمني ومالي متأخرين فين متقدمين فين · مصروفات يوم بيوم · رواتب تتحمل تلقائياً على المشروع بالفرق الموزعة — إيه اللي ناقص فعلياً لسه مفكرناش فيه؟ داش بورد — وهبعتلك شكلها».
> **النموذج المرفق:** `upload/03-MOH-SASH-Oct 26- Dashoard.pdf` — لوحة استشاري حقيقية لمشروع مستوصف صباح السالم الجنوبي (نفس مشروع BOQ المستورد — 980,037.05 د.ك): رأس زمني (243/450 يوماً) · تقدم إجمالي ثلاثي (مبكر 52.01% / متأخر 49.74% / فعلي 52.23%) · منحنى S (قيمة شهرية + تراكمي) · تقدم بالتكلفة (511,916.05 = 52.23%) · جدول أداء 16 قسماً · فطيرة أوزان الأقسام.
> **الغرض:** تحويل هذا النموذج إلى لوحة **حيّة مشتقة حصراً** (G9) — أقوى من نموذجه بوضعين: EV برؤيتين (رسمي/ميداني) ومصروفات حقيقية تلقائية.

## 2) الفجوة الأولى — البرنامج الزمني للبنود (Schedule)

- **النموذج:** `BoqItem.plannedStart / plannedFinish` (String `YYYY-MM-DD` — نمط تواريخ المشروع، افتراض فارغ لا يكسر شيئاً).
- **الدخول:**
  1. شبكة إدخال/تحرير سريعة في قسم بنود الكميات (عمودان جديدان).
  2. **استيراد Excel بنمط «ارفع فيسحبه»** (نمط محلل BOQ القائم): صف = رقم بند `itemNo` + تاريخا بداية/نهاية — Primavera/MS Project يصدّران Excel جاهزاً؛ محلل نقية `schedule-parse.ts` يطابق البنود برقمها (المفتاح الموجود من الجلسة 4) ويحذّر عن غير المطابق.
- **ما تفتحه:** منحنى المخطط (PV) · تأخر كل بند بالأيام · إتمام متوقع مقابل مخطط — أي «متأخرين فين» حرفياً.
- **قرار v1:** منحنى «مبكر» حصراً (تاريخان لكل بند)؛ ثنائية مبكر/متأخر (Late كما في نموذجه) امتداد بعمودين إضافيين لاحقاً — لا تعمير مسبق.
- هذا يغلق حداً معلناً مرتين: field-execution-design §6 (لا جدولة للبنود) وdaily-report-forecast §6 (منحنى بلا مخطط).

## 3) محرك اللوحة — EVM (إدارة القيمة المكتسبة): الإجابة الاحترافية على «متأخرين فين متقدمين فين»

كل المدخلات **موجودة ومشتقة** — الجديد هو تجميعها (لا أرقام يدوية في اللوحة إطلاقاً):

| المؤشر | المعادلة | مصدره في ConTrack |
|---|---|---|
| **PV** قيمة المخطط حتى اليوم | Σ قيمة البنود التي `plannedFinish ≤ اليوم` | ج1 × أسعار البنود |
| **EV** القيمة المكتسبة — برؤيتين | **رسمي**: Σ أسطر المستخلصات المعتمدة · **ميداني**: Σ تنفيذ × سعر البند | ز1 + د1 |
| **AC** التكلفة الفعلية | Σ سندات الصرف على العقد + Σ رواتب محملة (`LaborAllocation.amount`) + مواد مصروفة على بنوده | قائم كله |
| **BAC** الميزانية عند الاكتمال | قيمة العقد المعدلة (أصل + ملاحق معتمدة) | قائم |
| **SPI** = EV/PV | مؤشر التقدم الزمني: <1 متأخر | مشتق |
| **CPI** = EV/AC | مؤشر كفاءة التكلفة | مشتق |
| **EAC** = BAC/CPI | تقدير الكلفة النهائية | مشتق |
| تأخر البند | اليوم − `plannedFinish` (لغير المكتمل) | مشتق |

- **توأمة الروح:** EV برؤيتين (رسمي/ميداني) = نفس BOQ المزدوج — SPI رسمي (فوترة) وSPI ميداني (واقع موقع)، والفجوة بينهما تشخيص فوترة لا تضارب حسابي.

## 4) إجابة «إيه اللي ناقص فعلياً؟» — القائمة الصريحة

1. **الجدولة الزمنية للبنود** (§2) — بدونها لا «متأخرين فين» إطلاقاً؛ هي المدخل الناقص الوحيد.
2. **مؤشرات EVM** (§3) — SPI/CPI/EAC: مكوناتها منفصلة في النظام منذ الجلسات الأولى ولم تُجمع قط.
3. **معدل الحرق النقدي**: المصروفات/يوم (سندات + رواتب) → كم يوماً تمشي السيولة المتبقية.
4. **عتبات إنذار معلنة**: SPI<0.95 أو CPI<0.95 أو تأخر بند > N يوماً → بطاقات تحذير (العتبات في Settings — قابلة للضبط لكل شركة).
5. **أوزان الأقسام** (الفطيرة في نموذجه): مشتقة حصراً `قسم ÷ الإجمالي` — رخيصة ولم تدخل أي تصميم سابق.
6. ما ليس ناقصاً: كل ما عدّه المالك (§1) — فالبناء الحقيقي: جدولة ← محرك ← لوحة.

## 5) اللوحة — مكوناتها (مطابقة نموذج المالك + تفوقنا)

تصميم RTL بهوية NOVA (DEVLOG §2) · جوال 375 بلا تمرير أفقي · شريط سفلي مثبت:

1. **بطاقة الرأس** (نموذج قسمة الرأس في PDF): المشروع · المدة/المنقضي بأيام ونسبة · البداية والإتمام المتوقع.
2. **التقدم الإجمالي — 4 أعمدة بدل 3 في نموذجه**: مخطط (PV%) · **رسمي** (EV مستخلصات) · **ميداني** (EV يومية — ما لا يملكه استشاريه إطلاقاً) + شارات SPI/CPI.
3. **منحنى S ثلاثي**: مخطط تراكمي · رسمي تراكمي · ميداني تراكمي (طبقة رابعة عن نموذجه).
4. **تقدم الأقسام**: جدول الأقسام بأداء فعلي % (مثل قائمة نموذجه) + عمودا «مخطط %» و«فارق بالأيام» + الفطيرة الدائرية للأوزان (§4.5).
5. **المال**: قيمة العقد المعدلة · المفوتر · المُحصّل · المحتجز المعلق · **المصروفات الفعلية (سندات + رواتب محملة + مواد)** · النقد المتبقي · معدل الحرق (§4.3).
6. **التحذيرات**: أعلى بنود التأخر · استباق فوترة · بنود متوقفة — **نفس محرك التنبؤ** لا لوحتان.
7. **الطباعة**: زر طباعة المتصفح يخرج صفحة تشبه نموذجه PDF — للعرض على العميل/الاستشاري.
- **مصادرها حصراً:** نواة نقية `src/lib/dashboard-core.ts` + `GET /api/contracts/[id]/dashboard` (حرس `screen_contracts`) — بلا أي حالة مخزنة.

## 6) مراحل التنفيذ

| المرحلة | النطاق | الاعتمادية |
|---|---|---|
| **ج1** | الجدولة: عمودا التاريخين + استيراد Excel + شبكة إدخال | — |
| **ج2** | `dashboard-core` + EVM + مسار اللوحة | ج1 (PV) · ز1 (EV رسمي) · د1 (EV ميداني) |
| **ج3** | واجهة اللوحة + الطباعة + عتبات الإعدادات | ج2 |

**الترتيب الكلي المحدَّث:** ز1 ← ز2 ← ز3 (+ د1 متوازياً) ← ج1 ← م1 ← ج2 ← ج3 ← م2 ← م3.
ج2 يعمل **تدريجياً**: بلا ج1 يعرض EV/AC/CPI فقط؛ بلا ز1 يكتفي بـEV ميداني حصراً — لا انسداد انتظاراً.

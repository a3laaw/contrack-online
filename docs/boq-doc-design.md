# وثيقة جدول الكميات المستقلة (BOQ Doc) — «الـBOQ حاجة والبنود حاجة تانية»

> **المصدر:** قرار المالك 2026-11 (محادثة مباشرة):
> «بنود العقد حاجة والـBOQ حاجة تانية — لسه لما نعمل العقد ونربطه مع BOQ»
> ثم تحديد الموضع: «اذا في الاعدادت يكون مكان للـBOQ».
> **الغرض:** وثيقة BOQ تُبنى **قبل** العقد (شجرة أقسام وبنود)، وعند التعاقد يتربط
> بها العقد وتُنسخ بنودها إلى بنود العقد — تطوير لا بناء جديد فوق نموذجي
> `BoqItem` ومحلل `boq-parse` القائمين (قرار docs/nova-code-review.md §6).

---

## 1) المشكلة والمفهوم

النظام القائم يملك «بنود العقد» فقط (`BoqItem.contractId` إلزامي) — البنود لا وجود
لها قبل العقد. لكن دورة العمل الكويتية الحقيقية:

```
مناقصة تجي بجدول كميات (BOQ) → تسعير → فوز → توقيع عقد يتربط بالجدول
→ مستخلصات وتنفيذ على بنود العقد
```

يعني الـBOQ وثيقة مستقلة سابقة للعقد، تحتاج حياة خاصة: بناء يدوي للشجرة،
استيراد إكسل، حالة جاهزية، ثم ربط بالعقد.

## 2) قرار النموذج (المرحلة أ — المنفذة)

نموذجان جددان في `prisma/schema.prisma`:

| الجدول | الغرض | الحقول المفتاحية |
|---|---|---|
| `boq_docs` (`BoqDoc`) | الوثيقة | name · projectName/clientName/consultantName · `status` (draft/ready) · notes |
| `boq_doc_items` (`BoqDocItem`) | بنود الشجرة | docId(Cascade) · itemNo · divisionCode/divisionName · description · qty/unit/unitPrice · amount · sortOrder |

- **الشجرة مشتقة لا مخزّنة** — نفس قرار «مشتق لا مخزّن» في وحدة المشاريع:
  الأقسام تتجمع من `divisionCode` للبنود (نفس هوية محلل الاستيراد)، بلا جدول أقسام.
- **صفر كسر** — العقود القائمة «بنود مباشرة» كما هي؛ كل مسارات المستخلصات/الباطن/
  التنفيذ/المخازن تتغذى على `BoqItem` بلا أي تغيير.

## 3) المواضع

- **الإعدادات → تاب «▦ جدول الكميات BOQ»** (`boq-docs` — adminOnly — انحراف ويب
  معتمد بقرار المالك، بعد أنواع العقود) + بند شل مطابق (`boq-docs-config`).
- الحرس الخادمي: `adminGuard` (بيانات إعدادات — المدير/المطور) على كل المسارات.

## 4) المسارات الخادمية

| المسار | الدور |
|---|---|
| `GET/POST /api/boq-docs` | قائمة (عدد بنود + إجمالي لكل وثيقة) / إنشاء |
| `GET/PATCH/DELETE /api/boq-docs/[id]` | تفاصيل+بنود / تعديل بيانات وحالة / حذف (Cascade) |
| `POST /api/boq-docs/[id]/items` | إضافة بند يدوي (amount = كمية×سعر) |
| `PATCH/DELETE /api/boq-doc-items/[id]` | تعديل (إعادة حساب المبلغ) / حذف |
| `POST /api/boq-docs/[id]/import` | نفس محلل `boq-parse` — FormData file + mode=preview\|run |

**قاعدة الإجمالي (موحّدة مع مسار بنود العقد):**
`total = itemNo ? amount : qty×unitPrice` — المستورد (له رقم بند) يأخذ مبلغ
الملف الأصلي حصراً، واليدوي كمية×سعر؛ البنود المشمولة (INCLUDED) تبقى 0 كما في
الملف وملخصه — بهذا يطابق إجمالي الوثيقة الإجمالي العام في الملف (تحقق 1,020,037.050).

**الاستيراد:** معاينة (أقسام + عينة 8 بنود/قسم + تحذيرات + تحذير الإلحاق) ثم تنفيذ
`createMany` إلحاق لا استبدال — بنفس قواعد docs/boq-import-design.md §2.5.

## 5) الواجهة (settings/boq-docs-tab.tsx)

- **قائمة الوثائق:** جدول سطح مكتب (الوثيقة/المشروع/المالك/الحالة/البنود/الإجمالي)
  وبطاقات جوال + حوار إنشاء (الاسم إلزامي) + تعديل + حذف بتنبيه.
- **تفاصيل الوثيقة:** ترويسة (الحالة + تعيين جاهزة للربط/إرجاع لمسودة + إحصاءات:
  أقسام/بنود/إجمالي) + شريط بحث + زرا **إضافة بند** و**استيراد ملف BOQ**.
- **الشجرة:** رأس قسم قابل للطي (شارة الكود + الاسم + عدد البنود + إجمالي قسمي)
  وبنود تحته (جدول سطح مكتب / بطاقات جوال). الافتراضي المشتق: فتح الكل ≤60 بنداً،
  طيّ للكبيرة — وتعديل المستخدم للطي يُحفظ حالياً (state مشتق بلا useEffect).
- **حوار البند:** رقم البند + القسم (من الأقسام القائمة / «قسم جديد» بكود واسم /
  بلا قسم) + الوصف + الكمية + الوحدة (نص حر بمقترحات) + سعر الوحدة + إجمالي حي.

## 6) الحالة والدورة

`draft (مسودة)` → «تعيين جاهزة للربط» → `ready (جاهزة)` — الجاهزة وحدها ستظهر
في منتقي الربط عند إنشاء العقد (المرحلة ب). العودة لمسودة متاحة ما لم يتربط.

## 7) المراحل القادمة (بانتظار إشارة المالك)

- **ب — الربط:** عند إنشاء العقد حقل «ربط BOQ» (الجاهزة حصراً) + زر «نسخ بنود
  BOQ إلى العقد» — **نسخ لحظة الربط لا ربط مرجعي** (العقد الموقّع ثابت، نفس مبدأ
  تثبيت اللقطة عند الاعتماد)، وكل بند منسوخ يحمل مرجع أصله (sourceDocItemId
  مستقبلاً) لتتبع الفروق. التعديلات اللاحقة على الأصل لا تلمس العقد — تمر بأوامر التغيير.
- **ج — العرض:** بطاقة «BOQ المرتبط» في مركز العقد + مقارنة الفروق مع الأصل.

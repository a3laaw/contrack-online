# تصميم موديول المبيعات — عروض الأسعار ببيت مستقل · نقاط البيع المتكاملة بالمخازن — ConTrack Online

> وثيقة تصميم للاعتماد — بلا أي كود. المرجع: كتالوج الموديولات (`code: "sales"` المعلن: «عروض الأسعار وفواتير المبيعات العامة ونقاط البيع») + المحركات القائمة الجاهزة للاستثمار: **الفواتير** (Task 107: بنود وخصومات وقيد إصدار وتخصيص FIFO وإلغاء بعكسي وPDF — وتدعم «بلا عقد» أصلًا) + **عروض الأسعار** (نماذج وAPI كاملة من المرحلة 9 بحالة آلة مغلقة، بواجهة حوار فقط داخل شاشة العملاء) + **المخازن** (docs/warehouses-design.md: صرف بلقطة وفحص خط زمني وبذر مؤجل).
> الحالة: بانتظار موافقة المستخدم على هذا التصميم قبل التنفيذ.

## 0) النطاق المعتمد — موديول يُبنى على القائم لا بجانبه

| # | البند | الوضع الحالي | ما يضيفه المبيعات |
|---|-------|---------------|---------------------|
| 1 | عروض الأسعار | نماذج + API + آلة حالات (جديد/مرسل/مقبول/مرفوض/منتهي) — بواجهة حوار حصرًا داخل شاشة العملاء، وبلا أي مستدعٍ للتحويل | **بيت مستقل** بشاشة كاملة + **تحويل عرض→فاتورة بيع** (أول مستدعٍ واجهة في تاريخ التحويل) |
| 2 | فواتير المبيعات العامة | المحرك كامل ويعمل بلا عقد منذ Task 107 — تملكها المحاسبة (تبويب الفواتير) | **لا شاشة جديدة** — نقاط البيع تصدر فيها، والتحويل من العروض يصبّ فيها (درس G3/G5: لا ازدواج شاشة) |
| 3 | نقاط البيع | لا شيء | **شاشة بيع سريع** تُخرج بمعاملة واحدة: فاتورة + سند قبض آلي + إذن صرف مخزني آلي — كلها بمحركات القائمة حصرًا |
| 4 | تكامل المخازن | الصرف على العقود حصرًا (د7 المخازن) | صرف بيع آلي للمواد المخزنية المبيعة — **بلا عقد** ومرتبط بالفاتورة، بقيد تكلفة مبيعات مستقل |

## 1) الفلسفة — نفس الأسس بلا استثناء

- **صفر جداول جديدة (جوهر الموديول)**: كل ما يلزم عمودان قابلان للفراغ على الكيانات القائمة (`InvoiceItem.itemId` · `StockDoc.saleInvoiceId`) + بذران مؤجلان (عميل نقدي · حساب 5116) — درس G3/G5 بأبهى صوره: الميزة تُبنى من محركات موجودة مُجرَّبة، فلا كيانات ميتة ولا مسارات موازية.
- **خط واحد للمالية**: كل قيد عبر المحركات الثلاثة القائمة حصرًا — قيد الإصدار (`invoice_issue` مدين العملاء/دائن الإيراد)، السند (قواعد الترحيل)، الصرف المخزني (`inventory_issue`) — لا قاعدة ترحيل جديدة ولا مسار كتابة ثانٍ.
- **مصدر سداد واحد هو السند**: الدفع الفوري في نقاط البيع = **سند قبض آلي** يخصَّص بآلية FIFO القائمة — المبدأ الحاكم لـTask 107 محفوظ حرفيًا.
- **د7 المخازن يكتمل لا ينقض**: قاعدة «الصرف على العقود» تتوسع إلى «الصرف على عقد **أو** على فاتورة بيع» — فلتر تقارير العقود (`contractId != null`) يجعل بيع النقاط شفافًا عن تكلفة العمالة والمواد التعاقدية.
- **النواة النقية أولًا** (consulting-v1): حساب أسطر البيع، خريطة عرض→فاتورة، التحقق المغلق — دوال نقية في `sales-core.ts` + اختبارات bun قبل أي ربط.

## 2) قرارات تحتاج اعتمادك (القيم الافتراضية المقترحة — تُعدل عند الاعتماد)

| # | القرار | المقترح | البديل |
|---|--------|---------|--------|
| د1 | ملكية الشل | تبويب **«المبيعات»** واحد (Store) بقسمين: «عروض الأسعار» و«نقاط البيع» — تبويب الفواتير يبقى بملكية المحاسبة كما هو (شاشة واحدة لكل مستند) | نقل تبويب الفواتير للمبيعات (يكسر الشركات بلا موديول مبيعات — مرفوض) |
| د2 | عروض الأسعار | البيت المستقل يستهلك **نفس API القائم بلا تغيير** (نفس آلة الحالات والترقيم QUO) + زر «تحويل إلى فاتورة بيع» يعبي فاتورة عامة جديدة من بنود العرض ويوسم العرض في ملاحظاته — التحويل إلى عقد تبقى دالته بلا واجهة (حدود) | إعادة بناء العروض بموديل جديد (ازدواج — مرفوض) |
| د3 | نقاط البيع | شاشة بيع سريع: عميل اختياري (الافتراضي **العميل النقدي المبذور**) + أسطر من أصناف المخازن (بحث بالاسم يملأ الوحدة والتكلفة) أو أسطر حرة وصفًا + خصم% للسطر (محرك الفواتير نفسه) + وسيلة دفع فورية ⇒ «إتمام البيع» بمعاملة واحدة | فاتورة معلقة تُسدد لاحقًا (عبر شاشة الفواتير القائمة — يبقى ممكنًا يدويًا بلا نقاط بيع) |
| د4 | تكامل المخزون | سطر الفاتورة بـ`itemId` اختياري: المخزني يولّد **إذن صرف آليًا** (بلا عقد — مرتبط بالفاتورة `saleInvoiceId`) بقيد **مدين 5116 «تكلفة المبيعات»** (بذر مؤجل شقيق 5110) / دائن 1160 — سطر حر بلا صنف = بلا صرف ولا تكلفة | بيع مخزني بلا حركة مخزون (يفقد جرد المواد الفائضة حقيقتها — مرفوض) |
| د5 | قاعدة الصرف | تتوسع: `issue` يتطلب `contractId` **أو** `saleInvoiceId` — وفحص المتاح نفسه بإعادة تشغيل الخط الزمني (د4 المخازن حرفيًا)، وعدم توفر الكمية يرفض البيع كله برسالة عربية بالصنف والمتاح | سماح بسالب (يفسد المتوسط المرجحي — مرفوض) |
| د6 | العميل النقدي | بذر مؤجل بنمط المخازن: «عميل نقدي — نقاط البيع» بمفتاح ثابت لكل شركة عند أول بيع (لا يظهر بالتنسيق المرئي للعملاء بأي تغيير سوى كونه عميلًا) — `customerId` الإلزامي في الفواتير والذمم لا يُمس | جعل customerId اختياريًا (يكسر تقارير الذمم والأعمار — مرفوض) |
| د7 | السداد الفوري | سند **قبض (RV)** آلي بوسيلة الدفع المختارة (حسابات الصندوق/البنك من الدليل) + تخصيص FIFO القائم يحدّث `paidAmount` والحالة — لا خصم نقدي موازٍ ولا مسار سداد ثانٍ | قيد مباشر مدين نقد/دائن إيراد (يضيّع سندات القبض والتسوية — مرفوض) |
| د8 | الإلغاء | `void` الفاتورة (المدير) ⇒ **داخل نفس المعاملة**: عكس قيد الإصدار + إلغاء سند القبض الآلي بعكسه + إلغاء إذن الصرف المرتبط بعكسه — لا أراضٍ معلقة ولا مخزون معلّق | إلغاء الفاتورة وحدها (يبقي سندًا وصرفًا على فاتورة ملغاة — مرفوض) |
| د9 | الأسعار | يدوية حرة لكل سطر، مع عرض **التكلفة (المتوسط المرجحي)** معلوميًا للمخزني و**تحذير بيع تحت التكلفة** (توست أصفر غير مانع) — بلا قوائم أسعار ولا هامشيات مجدولة | قائمة أسعار للصنف (تأجيل معلن — حدوده §10) |
| د10 | الصلاحيات | مفتاح واحد `screen_sales` (نمط الشاشات التشغيلية، secretary:true) + `moduleGuard("sales")` على مسارات الموديول — والفواتير الناتجة تفتح بصلاحية `screen_invoices` القائمة كما اليوم | مفاتيح فرعية للنقطة/العروض (تأجيل معلن) |

## 3) المخطط (Prisma) — عمودان + علاقتان + بذران (صفر جداول)

```prisma
model InvoiceItem {
  // القائم كاملًا يبقى — إضافة واحدة:
  itemId  Int?       @map("item_id")
  item    StockItem? @relation(fields: [itemId], references: [id]) // سطر مخزني ⇒ صرف آلي — الفارغ سطر حر
}
model StockDoc {
  // القائم كاملًا يبقى — إضافة واحدة:
  saleInvoiceId Int?     @map("sale_invoice_id")
  saleInvoice   Invoice? @relation("SaleInvoiceDocs", fields: [saleInvoiceId], references: [id]) // إذن الصرف الآلي للبيع — SetNull مع حذف الفاتورة
}
// علاقة عكسية على Invoice: saleDocs StockDoc[] @relation("SaleInvoiceDocs")
// علاقة عكسية على StockItem: invoiceItems InvoiceItem[]
```

- **بذران مؤجلان بنمط `ensureOne`**: `ensureCashCustomer` (عميل «نقدي — نقاط البيع» برمز آلي من التسلسل القائم، ومفتاح تمييز بالملاحظات) و`ensureSalesAccounts` (5116 «تكلفة المبيعات» شقيق 5110) — يُستدعيان عند أول بيع.
- لا TENANT/BACKUP جديدة — الكيانات الثلاثة مسجلة أصلاً (درس T111 مستوفى سلفًا).

## 4) النواة النقية (`sales-constants.ts` + `sales-core.ts`)

- **حساب سطر البيع** (`posLineTotal`): `r3(qty × price × (1 − disc/100))` — مرآة محرك الفواتير، والإجماليات على الرأس محصلة محركًا.
- **خريطة عرض→فاتورة** (`mapQuotationToInvoiceItems`): بنود العرض (وصف/كمية/وحدة/سعر) تُترجم أسطر فاتورة بخصم صفري — العرض بلا بنود مرفوض، والمقبول/الجديد فقط قابلان للتحويل (المرفوض والمنتهي لا).
- **تحقق البيع** (`validatePosSale`): سطر واحد على الأقل؛ الكمية > 0 والسعر ≥ 0 والخصم 0–100؛ **السطر المخزني يلزم `itemId` صحيحًا نشطًا**؛ الدفع الفوري يلزم وسيلة دفع بحساب؛ البيع الآجل (بلا سند) مسموح للعميل المسمّى حصرًا (النقدي بلا سند = مرفوض — نقدًا بلا قيد قبض لا معنى له).
- **تحذير التكلفة** (`underCostLines`): أسطر المخزني بسعر < المتوسط المرجحي الحالي — قائمة أسماء تُعرض توستًا غير مانع.
- **تنسيقات العرض**: تسميات وسائل/حالات معاد استخدامها من الثوابت القائمة.

## 5) الخادم (`sales-server.ts` + المسارات)

- **`POST /api/sales/pos`** — المعاملة الواحدة الكبرى (كل خطوة عبر محركها القائم):
  1. `ensureCashCustomer` (إن لم يُسمَّ عميل) + `ensureSalesAccounts`
  2. فحص المتاح لكل الأسطر المخزنية بإعادة تشغيل الخط الزمني (د5) — الرفض يلغي البيع كله
  3. **إنشاء الفاتورة** بمحرك الفواتير (بلا عقد — بلا سقف فوترة) ⇒ قيد الإصدار `invoice_issue`
  4. **سند القبض الآلي** عند الدفع الفوري (`createVoucher` RV بوسيلة الدفع) ⇒ تخصيص FIFO على الفاتورة فورًا
  5. **إذن الصرف المخزني الآلي** لكل أسطر الأصناف (إذن واحد بأسطر متعددة — `snapUnitCost` من المتوسط المرجحي الخادمي حصرًا، `saleInvoiceId` يربطه بالفاتورة) ⇒ قيد `inventory_issue` بـ**مدين 5116 / دائن 1160** (بلا بُعد عقد)
  6. audit واحد شامل على الفاتورة + العدّادات للعرض
- **`POST /api/quotes/[id]/convert`** — تحويل عرض→فاتورة بيع (يستدعي مسار الفواتير العام بالبنود المخططة، ثم يوسم العرض بالملاحظة والتدقيق) — أول مستدعٍ واجهة لمنطق التحويل القائم بلا استخدام.
- **توسعة `void` الفاتورة** (`invoice-server`/مسار الإلغاء القائم): داخل معاملة الإلغاء القائمة تُضاف خطوة — إلغاء سندات القبض الآلية (`posCreated` مميزة بالوصف؟ لا: **سندات مرتبطة بفواتير تملك saleDocs**) وإلغاء `saleDocs` المرتبطة بقيدَي عكس — بترتيب: الصرف أولًا ثم السند ثم عكس الإصدار (التحقق: الفاتورة بلا saleDocs = السلوك القائم حرفيًا بلا تغيير).
- **قائمة نقاط البيع اليومية**: GET `/api/sales/pos?date=` — فواتير اليوم المولدة من النقطة (فلتر `saleDocs` أو علامة بسيطة؟ الأبسط: فواتير العميل النقدي + فواتير بأسطر مخزنية مرتبطة) — للعرض فقط بلا تقارير جديدة.

## 6) واجهة الشل والشاشة

- **الشل**: `ModuleId` يزداد `"sales"` + كتلة NAV_MODULES بند «المبيعات» (Store) بعد المخازن وقبل المحاسبة بقسمين (`view:"sales"`): «عروض الأسعار» (FileText، section:"quotes") و«نقاط البيع» (Calculator/ShoppingCart، section:"pos") — `perm: screen_sales` — إخفاء تلقائي عبر navModulesFor، والكتالوج: `available:true` + `navModules:["sales"]`.
- **قسم العروض** (SalesView → QuotesSection): جدول كامل بفلاتر الحالة/العميل/البحث (نفس API القائم) + حوار إنشاء/تعديل ببنود (مرآة حوار العملاء بشاشة كاملة) + أزرار آلة الحالات القائمة + **«تحويل إلى فاتورة بيع»** للمقبول/الجديد ⇒ يفتح الفاتورة المولدة.
- **قسم نقاط البيع** (PosSection): شاشة سريعة واحدة — عميل (SearchableSelect افتراضي «نقدي») + شبكة أسطر (بحث صنف/سطر حر + كمية + سعر مع التكلفة ظاهرة + خصم%) + وسيلة دفع + ملاحظة + «إتمام البيع» ⇒ توست برقم الفاتورة والسند والإذن + **طباعة إيصال** (نمط طباعة الفاتورة المتصفحية القائمة) + شريط «مبيعات اليوم» (عدد ومحصلة).
- **موبايل 375**: أسطر مكدسة وأزرار بعرض كامل — بلا تمرير أفقي (معيار الموديولات).
- تقرير الفواتير القائمة (المحاسبة) يعرض فواتير النقطة بلا أي تغيير — وعمود «تكلفة المبيعات» لا يُضاف لشيء (القوائم تلتقط 5116 طبيعيًا من الأستاذ).

## 7) دروس NovaFlow والنظام المطبقة

| الدرس | التطبيق في المبيعات |
|-------|---------------------|
| G3/G5 — لا جدول بلا استخدام | صفر جداول جديدة؛ كل الكيانات القائمة مستثمرة فورًا (عروض نائمة تُوقظها واجهة، فواتير بلا عقد تُستثمر، محرك مخازن يتوسع عمودًا واحدًا) |
| خط واحد للمالية | ثلاثة قيود عبر ثلاثة محركات قائمة — لا قاعدة ترحيل ولا مسار جديد |
| مصدر سداد واحد | سند القبض الآلي + FIFO القائم — لا خصم نقدي موازٍ |
| G8 — الإلزامية | الدفع الفوري بلا وسيلة مرفوض؛ النقدي بلا سند مرفوض؛ السطر المخزني بلا صنف صحيح مرفوض |
| د7/د4 المخازن | قاعدة الصرف تتوسع لا تنقض، وفحص الخط الزمني نفسه، واللقطات الخادمية نفسها |
| د8 — الإلغاء الشامل | void الفاتورة يسحب السند والإذن معه داخل المعاملة — لا أثر يتيم |
| T111 | لا جداول جديدة أصلًا — العمودان على كيانات مسجلة |

## 8) خطة التنفيذ والاختبارات (بعد الاعتماد)

1. **السكيما**: عمودا `InvoiceItem.itemId` و`StockDoc.saleInvoiceId` + العلاقتان العكسيتان + `db:push` (تغيير إضافي قابل للفراغ — لا ترحيل بيانات).
2. **النواة النقية + الاختبارات**: `sales-constants.ts` + `sales-core.ts` (خطوط/خريطة/تحقق/تحذير تكلفة) — `tests/sales-core.test.ts` قبل أي ربط.
3. **الخادم**: `sales-server.ts` (البذران + المعاملة الكبرى) + `POST /api/sales/pos` + `POST /api/quotes/[id]/convert` + توسعة void الشاملة + حماية كل مسار جديد بالحرسين.
4. **الواجهة**: الشل + `SalesView` + `QuotesSection` + `PosSection` + ربط ConTrackApp.
5. **تحقق حي** (شركة بذر بموديولات مقاولات+مخازن+مبيعات ثم تنظيف شامل): إدخال 10 كيس @1.250 ⇒ بيع نقدي سطران (5 كيس @2.000 مخزني + سطر حر 3.000) ⇒ **فاتورة 13.000 + سند RV + إذن صرف آلي + قيود ثلاثة** (إيراد 13/ذمم · صندوق 13/ذمم · تكلفة مبيعات 6.25/مخزون) ⇒ رصيد المخزن 5 بقيمة 6.25 ⇒ العميل النقدي مبذور مرة واحدة ⇒ بيع بكمية 99 ⇒ رفض عربي بالمتاح ⇒ إلغاء الفاتورة ⇒ **عكس الثلاثة والرصيد يعود 10** ⇒ عرض مقبول ⇒ تحويل لفاتورة ⇒ الفاتورة في الشاشة القائمة بلا عقد ⇒ موبايل 375 ⇒ تنظيف شامل (صفر صفوف).
6. **push ومراجعة الإنتاج** — النشر التلقائي عبر main.

## 9) حدود الموديول (ما لا يُبنى عمدًا)

- بلا طباعة حرارية/باركود/قارئ سكانر (طباعة المتصفح وPDF الفواتير القائمة تكفيان) ·
- بلا بوابات دفع إلكتروني أو KNET (وسائل الدفع = حسابات الصندوق/البنك القائمة) ·
- بلا قوائم أسعار ولا هامشيات مجدولة ولا عروض مؤقتة (السعر يدوي مع تحذير التكلفة — د9) ·
- بلا تحويل عرض→عقد بواجهة (الدالة القائمة بلا مستدعٍ تبقى كما هي — نطاق العقود) ·
- بلا تقارير مبيعات جديدة (شاشة الفواتير القائمة وفلاترها تكفي) · بلا تعدد نقاط بيع/درجات/إغلاق درج نقدي ·
- بلا ولاء عملاء ولا خصومات مجدولة ولا بيع بالتقسيط (الآجل = فاتورة عامة تُسدد من شاشة الفوترة القائمة) ·

# تصميم ر4 — الموردون وأوامر الشراء · مسار شراء المواد — ConTrack Online

> وثيقة تصميم للاعتماد — بلا أي كود. المرجع: موديول Purchase في خريطة Odoo المعتمدة (`docs/odoo-modules-reference.md`: RFQ، أوامر شراء، موردون — **بلا** Vendor pricelists ولا Requisitions) + الخارطة المعتمدة (`docs/development-roadmap.md` ر4). المحركات القائمة الجاهزة للاستثمار: **المخازن** (`docs/warehouses-design.md`: إدخال بلقطة تكلفة ومتوسط مرجحي وقيد فوري — `entrySource: cash|credit|return`) + **سندات الصرف** (Voucher payment بقواعد الترحيل والتخصيص) + طباعة PDF الخادمية القائمة.
> **الحالة: بانتظار موافقة المالك على هذا التصميم قبل التنفيذ.**

## 0) النطاق المعتمد — مسار الشراء يُبنى من المحركات القائمة لا بجانبها

| # | البند | الوضع الحالي | ما يضيفه الشراء |
|---|-------|---------------|------------------|
| 1 | المورد | لا كيان — الإدخال الائتماني يخزن «الطرف» **نصًا حرًا** (`StockDoc.party`) | جدول **موردون** بترقيم ذري + بيانات اتصال — والموردون الكُتّاب الحاليون يعاملون كنص كما هم (بلا ترحيل إجباري) |
| 2 | طلب → أمر شراء | لا مسار شراء بموافقاته — المخازن تغطي حركة الأصناف بعد دخولها | **أمر شراء PO** بآلة حالات مغلقة: مسودة ← مرسل للمورد ← جزئي ← مستلم / ملغى + طباعة PDF للمورد |
| 3 | الاستلام | الإدخال يدوي داخل المخازن | زر **«استلام»** على الأمر يولّد **إذن إدخال آليًا** عبر دالة الإدخال القائمة حرفيًا (لقطاتها وقيد `inventory_entry` ومتوسطها المرجحي) — كليًا أو جزئيًا بكميات سطرية |
| 4 | السداد | سندات صرف عامة | سند صرف **مورَّد**: يستخدم محرك السندات القائم + ربط معرفي اختياري بالأمر لكشف حساب المورد (قرار د6) — **لا مطابقة إلزامية ولا ذمم موردون** |
| 5 | ربط التكلفة بالعقد | الصرف على العقود قائم | لا تغيير — المواد تدخل المخزن ثم تُصرف على العقود بالقائم؛ ربط الأمر بعقد **غير مالي** فقط إن طلب المالك (د5) |

## 1) الفلسفة — نفس الأسس بلا استثناء

- **صفر محركات جديدة**: الإدخال المخزني والقيد المزدوج والسند وطباعة PDF كلها دوال قائمة مُجرَّبة — الشراء يضيف «الطلب والاتفاق» فوقها، لا مسار كتابة ثانٍ (درس G3/G5 بأبهى صوره — كما فعلت المبيعات بـ`saleInvoiceId`).
- **لقطة مجمّدة على الأمر**: سعر الشراء يجفّف على سطر الأمر لحظة الحفظ، والإدخال الآلي يحمل **لقطة سعر الأمر** إلى `snapUnitCost` — المتوسط المرجحي يحسبه محرك الإدخال القائم تلقائيًا (د2 المخازن محفوظ حرفيًا).
- **استلام لا يتجاوز**: مجموع المستلم عبر الإذنات لا يتجاوز المطلوب — الزيادة تُرفض برسالة عربية بالصنف والأرقام (المفهوم المضاد للصرف المخزني د4/د5 المخازن).
- **أمر بلا مسودات معلقة**: الحالة مغلقة الانتقالات، والملغى يمنع الاستلام نهائيًا — والأمر جزئي يبقى مفتوحًا حتى اكتمال كل السطور.
- **النواة النقية أولًا** (نمط consulting-v1): آلة حالات الأوامر وحارس الاستلام الزائد ومجاميع الاستلام — دوال نقية في `purchase-core.ts` + اختبارات bun قبل أي ربط.

## 2) قرارات تحتاج اعتمادك (القيم الافتراضية المقترحة — تُعدل عند الاعتماد)

| # | القرار | المقترح | البديل |
|---|--------|---------|--------|
| د1 | الملكية والبلاطة | موديول **«الشراء»** مستقل (`purchase`) بالكتالوج بلوحتين: «أوامر الشراء» + «الموردون» — مفتاح `screen_purchase` (secretary:true) + `moduleGuard("purchase")` | تبويب داخل المخازن (يخلط حركة الأصناف بمسار الطلب — والمرجع Odoo يفصل `purchase` عن `stock` بجلته) |
| د2 | سطر أمر الشراء | **صنف مخزني إلزامي** (`itemId` FK) + كمية + سعر لقطة + ملاحظة حرّة — لا سطور وصف حر (لأن الاستلام يولّد إذن إدخال سطره إلزامي الصنف G7) | سطر حر بلا صنف لا يولّد إذنًا (ينشق الأمر عن المخزون — مرفوض) |
| د3 | آلة حالات الأمر | `مسودة · مرسل للمورد · جزئي · مستلم · ملغى` — الانتقالات: مسودة→مرسل للمورد/ملغى · مرسل للمورد→جزئي/مستلم/ملغى · جزئي→مستلم/ملغى — **مستلم وملغى نهائيان**؛ استلام أول يرفع «مرسل للمورد→جزئي» آليًا داخل المعاملة | حالات حرة بلا حرس (مرفوض — درس آلة العروض) |
| د4 | الاستلام الجزئي | مستلم لكل سطر يتراكم من إذن الإدخالات المولدة؛ الاستلام بكمية مطلوبة افتراضيًا والفاقد يبقى مفتوحًا — **الزيادة تُرفض** (المستلم+الجديد > المطلوب) | سماح بزيادة الاستلام (يفسد أمرًا «مستلمًا» مع طلب غير وارد — مرفوض) |
| د5 | ربط الأمر بعقد | `contractId?` **اختياري معرفي** للعرض والتقارير فقط — لا قيد ولا تكلفة تتأثر (المواد تُقيس تكلفة العقد لحظة الصرف بالقائم) | ربط إلزامي بعقد (شراء ما سفرًا لصيانة أو بيع لا عقد له يُمنع بلا داعٍ) |
| د6 | كشف حساب المورد | عمودان على `Voucher`: `partyType="supplier"` (إضافة لقائمة القيم) + `supplierId?` اختياري — سند صرف من شاشة الأمر يعبأ بهما آليًا، والكشوف القائمة (فلاتر null/not-null) تترجم 1:1 كما فعلت Task 105 | نص حر كما اليوم (يفقد كشف المورد معرفيته G11) |
| د7 | رقم الأمر والمورد | ترقيم ذري: `PO-####` عبر `nextNumberByKey("purchase_order:number","PO",4,tx)` و`SUP-####` للمورد بنفس النمط — بمزامنة العدّاد فوق الأرقام القائمة أول استخدام | max+1 (سباقات موثقة — مرفوض) |
| د8 | طباعة الأمر | PDF خادميًا نمط المطبوعات القائمة: ترويسة الشركة + بنود الأمر بلقطاتها + التوقيعات — زر طباعة على الأمر «مرسل للمورد» فصاعدًا | طباعة المتصفح (كسر نمط المطبوعات الرسمية — مرفوض) |
| د9 | موردون كُتّاب | بلا ترحيل إجباري — الإدخال الائتماني المباشر من المخازن يبقى قائمًا بالنص الحر كما هو؛ أمر الشراء هو الباب الجديد للكتابة المنضبطة | إجبار كل إدخال على مورد (يكسر الدخول السريع القائم المستقر — مرفوض) |

## 3) المخطط (Prisma) — ثلاثة جداول + عمودان على القائم

```prisma
model Supplier {
  companyId    Int       @default(1) @map("company_id")
  id           Int       @id @default(autoincrement())
  supplierCode String    @map("supplier_code")                  // SUP-#### ذري (د7)
  name         String
  phone        String    @default("")
  email        String    @default("")
  address      String    @default("")
  crNumber     String    @default("") @map("cr_number")         // السجل التجاري
  active       Boolean   @default(true)
  notes        String    @default("")
  createdAt    DateTime  @default(now()) @map("created_at")
  purchaseOrders PurchaseOrder[]

  @@unique([companyId, supplierCode])
  @@unique([companyId, name])
  @@map("suppliers")
}

model PurchaseOrder {
  companyId     Int       @default(1) @map("company_id")
  id            Int       @id @default(autoincrement())
  poNumber      String    @map("po_number")                      // PO-#### ذري (د7)
  supplierId    Int       @map("supplier_id")
  supplier      Supplier  @relation(fields: [supplierId], references: [id])
  orderDate     String    @map("order_date")                     // YYYY-MM-DD
  expectedDate  String    @default("") @map("expected_date")
  contractId    Int?      @map("contract_id")                    // د5 — معرفي للعرض حصرًا
  contract      Contract? @relation("PoContract", fields: [contractId], references: [id])
  status        String    @default("مسودة")                       // د3 — قائمة مغلقة
  totalAmount   Decimal   @default(0) @map("total_amount") @db.Decimal(18, 3) // مجمّد على الرأس
  receivedAmount Decimal  @default(0) @map("received_amount") @db.Decimal(18, 3) // قيمة المستلم تجمّد مع كل استلام
  notes         String    @default("")
  createdBy     Int?      @map("created_by")
  createdAt     DateTime  @default(now()) @map("created_at")
  updatedAt     DateTime  @updatedAt @map("updated_at")
  items         PurchaseOrderItem[]
  receipts      StockDoc[]                                       // إذن الإدخالات المولدة من هذا الأمر

  @@unique([companyId, poNumber])
  @@index([supplierId])
  @@index([companyId, status])
  @@map("purchase_orders")
}

model PurchaseOrderItem {
  companyId   Int           @default(1) @map("company_id")
  id          Int           @id @default(autoincrement())
  poId        Int           @map("po_id")
  po          PurchaseOrder @relation(fields: [poId], references: [id], onDelete: Cascade)
  itemId      Int           @map("item_id")                     // د2 — إلزامي
  item        StockItem     @relation("PoItemItem", fields: [itemId], references: [id])
  qty         Decimal       @db.Decimal(18, 3)                  // المطلوب
  receivedQty Decimal       @default(0) @map("received_qty") @db.Decimal(18, 3) // يتراكم مع كل استلام
  unitPrice   Decimal       @map("unit_price") @db.Decimal(18, 3) // لقطة سعر الشراء (د1 الفلسفة)
  amount      Decimal       @db.Decimal(18, 3)                  // = r3(qty × unitPrice)
  sortOrder   Int           @default(0) @map("sort_order")

  @@index([poId])
  @@index([itemId])
  @@map("purchase_order_items")
}
```
- على `StockDoc`: عمود اختياري واحد `purchaseOrderId Int?` (+ علاقة عكسية `receipts` أعلاه) — نمط `saleInvoiceId` حرفيًا، وحذف الأمر «مسودة» لا يلغي إذنًا (الأمر المُستلم منه يُمنع من الحذف أصلًا).
- على `Voucher`: عمودان اختياريان `supplierId Int?` + إدراج `"supplier"` في مفردات `partyType` (د6).
- لا enum — `PO_STATUSES` + الانتقالات في `purchase-constants.ts`.
- التسجيلات الإلزامية: `TENANT_MODELS` (suppliers قبل FK) + `BACKUP_MODELS` + `nav-structure.ts` + `modules-catalog.ts` (code "purchase" مُعلن «الموردون وأوامر شراء المواد») — قبل أي شاشة.

## 4) النواة النقية (`purchase-constants.ts` + `purchase-core.ts`)

- `PO_TRANSITIONS` خريطة مغلقة (د3) + `assertTransition(from,to)` برسالة عربية.
- `assertReceiptLine(order, received map, newQty)`: حارس الزيادة (د4) — يرفض برسالة تحمل الصنف والمستلم والمطلوب.
- `poStatusAfterReceipt(lines)`: يحدد جزئي/مستلم اشتقاقيًا من السطور.
- `supplierStatementRows(supplier)`: تجميع أوامره وسنداته للكشف (اشتقاقي بلا عدادات G9).

## 5) الخادم (المسارات — نمط المخازن/الاستشارات حرفيًا)

| المسار | الأفعال | الحراسة |
|--------|---------|---------|
| `GET/POST /api/purchase/suppliers` | قائمة + إنشاء | ترقيم SUP ذري · تفرّد الاسم لكل شركة |
| `GET/PATCH/DELETE /api/purchase/suppliers/[id]` | تعديل + حذف | **حذف مورد له أوامر مرفوض** برسالة عدد الأوامر (نمط حماية الاستشارات) |
| `GET/POST /api/purchase/orders` | قائمة بفلاتر (حالة/مورد/فترة) + إنشاء أمر ببنوده | مسودة/مرسل للمورد مباشرة عند الإنشاء · ترقيم PO ذري داخل المعاملة · مجاميع r3 |
| `GET/PATCH/DELETE /api/purchase/orders/[id]` | تفصيل + تعديل (مسودة فقط) + حذف (مسودة فقط) | تعديل بعد الإرسال مرفوض برسالة الحالة |
| `POST /api/purchase/orders/[id]/receive` | **استلام** بكميات سطرية → توليد إذن إدخال آلي عبر دالة المخازن القائمة داخل **المعاملة نفسها** + تحديث receivedQty والحالة والقيم المجمّدة | حارس الزيادة (د4) · الأمر الملغى/المستلم يرفض · القيد والإدراج والترقيم WI واحدٌ لا ثانٍ |
| `POST /api/purchase/orders/[id]/cancel` | إلغاء الأمر (إن لم يُستلم منه) | «مرسل للمورد» ببنود مستلمة يُمنع برسالة |
| `GET /api/purchase/orders/[id]/pdf` | طباعة الأمر (د8) | نمط المطبوعات القائمة |
| `GET /api/purchase/summary` | مؤشرات: أوامر مفتوحة بقيمها · مشتريات الشهر · موردون نشطون | اشتقاقية بلا عدادات |

- **سند المورد**: زر «سند صرف» في الأمر يفتح معالج السندات القائم معبأً (partyType="supplier" + supplierId + party لقطة الاسم) — منطق السند نفسه بلا تعديل (د6).

## 6) الواجهة — شل «الشراء» بلوحتين

- **البلاطة**: «الشراء» في الجانبي (+ مرآة `ModuleTabsBar` للهاتف) — لسان «أوامر الشراء»: بطاقة ملخص أعلى (مفتوح بقيمة · مستلم هذا الشهر · موردون نشطون بشارات NOVA) + جدول الأوامر (الرقم · المورد · التاريخ · المتوقع · الحالة شارة ملونة · القيمة · المستلم نسبةً · إجراءات) + لسان «الموردون»: جدول بسيط بحوار إنشاء/تعديل وشارة «مرتبط بأوامر».
- **حوار الأمر**: المورد (بحث/إنشاء سريع) · التاريخان · ربط عقد اختياري (د5) · بنود (صنف من المخازن ببحث يملأ الوحدة · كمية · سعر) بمجاميع حية · ملاحظات — إضافة بنود على «مسودة» حصرًا.
- **حوار الاستلام**: أسطر الأمر بالكمية المطلوبة/المستلمة سابقًا وحقل «الكمية المستلمة الآن» مع الباقي محسوبًا — زر «استلام» يولّد الإذن ويحدّث الصف فورًا؛ وعلى الأمر المستلم ظاهر «إذن الإدخال WI-####» رابطًا.
- الجوال 375 بلا تمرير أفقي · قوائم طويلة `max-h-96 overflow-y-auto` بتذييل مثبت · ألوان NOVA حصرًا (مسودة رمادي · مرسل للمورد كهرماني · جزئي أزرق ملكي معلوماتي · مستلم رمادي مكتمل · ملغى أحمر خطر).

## 7) دروس NovaFlow والنظام المطبقة

- **G3/G5**: لا مسار إدخال موازٍ — الاستلام **يستدعي** دالة الإدخال القائمة بعقودها الواحدة؛ لا سطور حرة بلا صنف.
- **G7/G11**: الحالات والموردون والأصناف معرفية — لا مطابقات نصية؛ لقطة اسم المورد للعرض فقط.
- **G9**: القيم المجمّدة على الرأس والسطور، والمؤشرات اشتقاقية بلا جداول عدادات.
- **معاملة واحدة**: الاستلام = إذن + قيد `inventory_entry` + تحديث الأمر + audit في معاملة واحدة؛ الإلغاء عكسي مرتبط بنمط السندات إن لزم مستقبلًا.

## 8) خطة التنفيذ والاختبارات (بعد الاعتماد)

1. النواة النقية + اختبارات bun (الانتقالات · حارس الزيادة · جزئي/مستلم اشتقاقيًا · كشف المورد).
2. السكيمة (3 جداول + عمودان اختياريان لا يلمسان شيئًا) + التسجيلات الأربع.
3. المسارات الثمانية مع معاملة الاستلام المُحورة على دالة المخازن.
4. الشل واللوحتين والطباعة → تحقق حي: مورد SUP-0001 → أمر PO-0001 بسطرين → إرسال للمورد → PDF → استلام جزئي (إذن WI + جزئي) → استلام الباقي (مستلم) → محاولة زيادة تُرفض برسالتها → سند صرف مورد معبأ → الكشوف → جوال 390 → lint صفر.

## 9) حدود الموديول (ما لا يُبنى عمدًا)

- لا RFQ/مناقصات متعددة الموردين (`purchase_requisition` تأجيل معلن) · لا قوائم أسعار موردون (Vendor pricelists) · لا فواتير موردون محاسبية ولا ذمم دائنة بمطابقة ثلاثية (السداد سندات كما اليوم) · لا تقييم/أداء موردون · لا اتفاقيات إطارات · لا بذور موردون مسبقة (تُنشأ عند أول استخدام — نمط البذر المؤجل).

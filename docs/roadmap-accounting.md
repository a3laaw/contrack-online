# خارطة الطريق: تحويل ConTrack إلى برنامج محاسبي كامل
> وثيقة عمل مرجعية — تُنفذ على مراحل، كل مرحلة تُسلَّم وتُرفع مستقلة دون كسر النظام القائم.
> ترقيم المهام يواصل سلسلة worklog.md (آخر مهمة: 101). العملة الحالية: د.ك (الكويت — الضريبة افتراضيًا 0 مع جاهزية تفعيلها).

---

## الجرد الواقعي (بعد Task 101)

### الأساسات الموجودة (نبني فوقها — لا نكسرها)
| المكوّن | الحالة |
|---|---|
| سندات قبض/صرف (Voucher) | ⭐ قوية: أنواع متعددة، ربط بالعقد/BOQ/الباطن/المشروع/مركز التكلفة، شيكات، إلغاء موثق، تجميع |
| شجرة حسابات مصروفات (ExpenseAccount) | جيدة: parent/children، allowPosting، includeInProfitability، kind=expense\|advance |
| قيود يومية (JournalEntry) | بسيطة: debit/credit كنصوص + مبلغ واحد — ليست مزدوجة متعددة الأطراف |
| فواتير (Invoice) | بدائية: رقم/عميل/عقد/مبلغ — بلا بنود/ضريبة/حالة سداد |
| بوابة الدفع (GatewayOp/BankLine/MatchAlias) | مطابقة بنكية وتحويلات بين الشركات — أساس ممتاز |
| كشف حساب، عهد، سلف، مطالبات | مكتملة |
| تقارير | العملاء والأرصدة، مستحقات المراحل، الإيرادات والمصروفات، تفصيل المصروفات، المقاولون |
| بنية SaaS | شركات معزولة (companyId على كل جدول)، صلاحيات، تدقيق، نسخ واستعادة (بما فيها رفع ملف — Task 101) |

### الفجوة المحاسبية (ما سنبنيه)
دليل حسابات كامل ← قيود مزدوجة آلية ← دفتر أستاذ ← ميزان مراجعة ← قوائم مالية ← فواتير متقدمة ← إغلاق سنوي.

## المرحلة أ — دليل الحسابات الكامل (Tasks 102–103)
> الأرضية التي يقف عليها كل شيء لاحقًا. لا تُقفز فوقها.

**Task 102 — نموذج Account + الترحيل الآمن**
- جدول جديد `Account`: `code` (فريد لكل شركة)، `name`، `type` (asset|liability|equity|revenue|expense)، `parentId`، `isLeaf`، `allowPosting`، `openingBalance`، `isActive`، `notes` — بنفس أنماط ExpenseAccount (companyId, sortOrder).
- بذر دليل مقاولات قياسي لكل شركة عند أول دخول (نمط seed-defaults الحالي): الأصول (نقد/بنك/عملاء/عقود تحت التنفيذ/محتجزات) — الخصوم (مورّدون/مقاولو باطن/محتجزات باطن/دفعات مقدمة) — حقوق الملكية (رأس المال/الأرباح المجمعة) — الإيرادات (إيرادات عقود/ملحقات/أعمال متنوعة) — المصروفات (مباشرة/غير مباشرة/إدارية).
- **جسر الهجرة**: كل ExpenseAccount يأخذ حقلًا جديدًا `accountId` (nullable) + أداة ربط آلية (مطابقة الاسم/المسار) + شاشة مراجعة الربط قبل التفعيل. القديم يبقى يعمل بالتوازي (feature flag `full_accounting`).
- شاشة «دليل الحسابات»: شجرة قابلة للطي بأكواد وأرصدة لحظية، إضافة/تعديل/تعطيل (منع حذف حساب عليه حركات)، بحث.
- API محمية adminGuard + AuditLog، اختبارات bun للبذر والترحيل وقواعد الشجرة (ليس للنوع أب ابنًا غير متوافق، لا posting إلا أوراقًا).

**Task 103 — الأرصدة الافتتاحية + ربط السندات**
- قيد افتتاحي موثق لكل شركة (من حقول openingBalance) قابل للتعديل قبل أول إغلاق.
- شاشات السندات تكتسب خيار «الحساب المحاسبي» (اختياري حتى المرحلة ب).

**معيار القبول**: دليل كامل مبذور، الحسابات القديمة مربوطة، الأرصدة الافتتاحية مدخلة، صفر خلل في الشاشات الحالية.

## المرحلة ب — محرك القيود المزدوجة (Tasks 104–105)
> قلب البرنامج. يستبدل قيود النصوص بقيود حقيقية آلية.

**Task 104 — JournalEntry/Line الجديد + محرك النشر**
- ترقية `JournalEntry` إلى رأس قيد: `entryNo` (تسلسل لكل شركة)، `entryDate`، `description`، `sourceType/sourceId`، `status` (draft|posted|cancelled)، `cancelledByEntryId`.
- جدول `JournalLine`: `entryId`، `accountId` (FK للدليل)، `debit`، `credit` (مجموعهما متساوٍ إلزاميًا)، `costCenter`، `contractId`، `boqItemId`، `subContractId`.
- محرك `postEntry(tx, lines[], meta)`: يتحقق توازن Dr=Cr، يقفل حسابات غير مسموح نشرها، يرفض تواريخ مقفلة، يكتب AuditLog — دالة واحدة تُستخدم من كل المصادر.
- **قواعد الترحيل الآلي** (قابلة للضبط في إعدادات الشركة): سند قبض ⇒ مدين نقد/بنك، دائن حساب العميل (أو الإيراد للمقبوضات المباشرة)؛ سند صرف ⇒ مدين حساب المصروف المرتبط، دائن نقد/بنك/شيكات مستحقة؛ إلغاء سند ⇒ قيد عكسي مرتبط.
- ترحيل القيود النصية القديمة: سكربت واحد يحولها لسطور (debit→Dr، credit→Cr) مع علم `migrated`.

**Task 105 — شاشة القيود + القيود الآلية**
- شاشة قيود: قائمة بالفلاتر (فترة/حساب/مصدر/حالة)، إنشاء قيد يدوي متعدد الأطراف بمعاينة توازن حية، معاينة/اعتماد/إلغاء بقيد عكسي.
- تفعيل الترحيل الآلي عند حفظ السندات والفواتير (خلف feature flag، مع سجل «قيد آلي #N من سند #M»).
- لوحة «القيود المعلقة» (draft بانتظار الاعتماد).

**معيار القبول**: كل سند جديد يولّد قيدًا متوازنًا آليًا، القديم مُرحّل، الإلغاء يعكس، والتقرير الموجود «الإيرادات والمصروفات» لا يتأثر.

---

## المرحلة ج — دفتر الأستاذ وميزان المراجعة (Task 106)
- **دفتر أستاذ** لأي حساب: حركاته من القيود المنشورة + رصيد جارٍ تراكمي + تصفية (فترة من–إلى، مركز تكلفة، عقد) + تصدير CSV/Excel/PDF بالنمط الحالي.
- **ميزان مراجعة**: أرصدة كل الحسابات حتى تاريخ (حركة + تراكمي)، فحص توازن عام Dr=Cr ظاهر في الواجهة، تجميع حسب النوع، تصدير.
- API قراءة محسنة (تجمع بالـSQL لا بالجافاسكربت — الجداول ستنمو).

**معيار القبول**: اختيار حساب من الدليل يفتح أستاذه فورًا؛ الميزان متوازن دائمًا بعد أي مجموعة قيود.

---

## المرحلة د — الفواتير المتقدمة والضريبة (Task 107)
- بنود فاتورة (جدول `InvoiceItem`: وصف/كمية/سعر/خصم)، نسبة ضريبة لكل بند (افتراضي من إعدادات الشركة = 0 للكويت، جاهز لأي نسبة)، إجماليات قبل/بعد.
- **حالة السداد**: مدفوع/جزئي/غير مدفوع — مربوطة بالسندات الحالية عبر allocation موجودة (لا ازدواج حساب).
- قيد آلي عند الإصدار: مدين العميل، دائن الإيراد + دائن ضريبة مستحقة.
- طباعة PDF برأس الشركة وترقيم تسلسلي (نمط nextNumber الحالي).
- شاشة الفواتير تُرقّى: تاب فواتير مع فلاتر حالة سداد + رابط «كشف الحساب» للعميل.

**معيار القبول**: فاتورة ببنود وضريبة تُصدر وتُطبع وتُقفل جزئيًا بسند، وقيد مزدوج متوازن خلفها.

## المرحلة هـ — القوائم المالية (Tasks 108–109)
**Task 108 — قائمة الدخل + الربحية لكل عقد**
- قائمة دخل: إيرادات − مصروفات = صافي الربح، للفترة وبالمقارنة بفترة سابقة، وبالفلاتر (مركز تكلفة/عقد/نوع حساب).
- تقرير ربحية عقد يُوحَّد مع دليل الحسابات (البوابة الحالية includeInProfitability تُحترم).

**Task 109 — المركز المالي + التدفقات النقدية**
- ميزانية عمومية: أصول = خصوم + حقوق ملكية + أرباح الفترة (حساب ربط آلي للنتيجة)، أرصدة حتى تاريخ.
- تدفقات نقدية مبسطة: تشغيلي/استثماري/تمويلي وفق تصنيف حسابات الدليل (حقل `cashFlowKind` اختياري على Account).
- كلاهما بصفحة طباعة أنيقة + تصدير Excel.

**معيار القبول**: القوائم تتوازن وتتطابق مع ميزان المراجعة، وتُطبع لعميل خارجي.

## المرحلة و — كشوف متقدمة وتقوية البوابة (Task 110)
- كشف حساب موحد (عميل/مورد/مقاول باطن): فواتير + سندات + قيود مباشرة بأرصدة جارية ورسوم تأخير اختيارية.
- تقرير أعمار الديون (30/60/90/أكثر) للعملاء والباطن.
- البوابة البنكية: حالة مطابقة رسمية لكل BankLine (مطابق/معلق/فرق تسوية) + قيد تسوية آلي للفروق والرسوم.

## قواعد التنفيذ الثابتة (لكل مهمة)
1. feature flag لكل قدرة جديدة — التفعيل التدريجي بلا كسر، مع سقوط آمن للشاشات الحالية.
2. كل جدول جديد يحمل `companyId` من اليوم الأول (عزل SaaS عبر غلاف db الحالي).
3. كل عملية محاسبية تكتب AuditLog؛ الأرقام تُحسب بالـSQL داخل المعاملات.
4. لا نعدل سلوك السندات/العقود الحالي إلا بإضافة اختيارية صريحة.
5. معيار الجودة المتوحد: bun test أخضر + tsc/lint نظيفان + تحقق متصفح (1366/375) + worklog + رفع ببروتوكول PAT.
6. الحساسية: أي مرحلة تمس القيود تُختبر أولاً على نسخة مرفوعة (زر الاستعادة من ملف — Task 101 — هو صافي الأمان).

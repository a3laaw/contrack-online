## 1) الفلسفة — نفس الأسس بلا استثناء

- **خط واحد للمالية (الأهم هنا)**: تخصيص العمالة **طبقة تحليلية بلا أي قيد محاسبي** — المسير يقيّد 5210 مرة واحدة على مستوى الشركة، والتخصيص يوزّع *معلوماتيًا* على العقود من خارج دفتر الأستاذ. لا مراكز تكلفة ولا قيود تحويل.
- **المعرّفية لا النصية**: كل ربط (موظف↔عقد، فريق↔موظف، تخصيص↔دفعة/عقد) بمفاتيح أجنبية — إعادة تسمية أي طرف لا تكسر شيئًا (نقض صريح لخطر NovaFlow الموثق).
- **اللقطات المجمّدة (Cost Snapping)**: سطر التخصيص يجفّف `snapMonthlyRate` و`amount` لحظة الكتابة — لا يُقرأ من ملف الموظف لاحقًا أبدًا.
- **مرآة الاستشارات**: `EmployeeAssignment` نسخة مطابقة البنية لـ`EngineerAssignment` القائم (نفس الحقول ونفس آلة سارية|منتهية) — نمط مجرّب داخليًا لا اجتهاد جديد.
- **النواة النقية أولًا**: كل الحسابات (مبالغ التخصيص، فحص سقف النسب، مخطط التوليد، فرق حقول الملف) دوال نقية في `hr-labor-core.ts` + اختبارات bun قبل أي ربط (consulting-v1).

## 2) قرارات تحتاج اعتمادك (القيم الافتراضية المقترحة — تُعدل عند الاعتماد)

| # | القرار | المقترح | البديل |
|---|--------|---------|--------|
| د1 | طبيعة تكلفة العمالة على العقود | **طبقة تحليلية بلا قيود** — الربحية تعرضها عمودًا منفصلًا، والقوائم المالية لا تُلمس | قيود تحويل بمراكز تكلفة (بنية جديدة تضرب «خط واحد») |
| د2 | جدول التعرفة | **حقل `monthlyCostRate` على الموظف** («التكلفة الشهرية على الشركة» — معرفي بحكم البنية) — فارغ/صفر ⇒ افتراضي = الراتب الأساسي لحظة التخصيص، وتاريخ التغييرات يوفره تدقيق الحقول (د8) | جدول تعرفة مؤرّخ منفصل (تكرار بلا حاجة الآن) |
| د3 | أساس التخصيص الشهري | **نسبة % من تكلفة الموظف الشهرية** (ليست ساعات) — التكليفات السارية مصدر توليد افتراضي + تحرير يدوي قبل التجميد | ساعات فعلية من الحضور (البصمة ليست لكل موظف — تأجيل) |
| د4 | الربحية | عمودان إضافيان فقط: **«تكلفة العمالة»** و**«الربح الشامل»** = المحصّل − المنصرف النقدي − العمالة — المعادلات القائمة بلا أي تغيير | دمج العمالة في «التكلفة الفعلية» النقدية (يشوّه المقارنة النقدية) |
| د5 | لحظة التجميد | التخصيص قابل للتحرير ما دامت الدفعة `draft|approved` — **عند `paid` تُجمّد للقراءة فقط**؛ الدفعات الملغاة تُتجاهل تقاريريًا | تجميد عند الاعتماد (يمنع توزيعًا دقيقًا قبل الدفع) |
| د6 | دور الأطقم | **تجميع تشغيلي**: توليد تكليفات جماعية بعقد واحد + فلترة عرض — لا أثر مالي مباشر للأطقم | الأطقم وحدة التكليف ذاتها (نِسَب متضاربة عند تعدد العضوية) |
| د7 | سقف النسب | مجموع تكليفات الموظف السارية **≤ 100%** — توليد تخصيص يتجاوز السقف يُرفض برسالة عربية تسمّي الموظف | تجاهل مع تحذير (يفسد مجموع التوزيع) |
| د8 | نطاق تدقيق الحقول | قائمة حقول مغلقة معلنة (القسم 6) — الإنشاء والحذف والتعطيل عبر نهاية الخدمة تبقى في التدقيق العام القائم (لا ازدواج) | تدقيق كل حقل بما فيه الجلسات (ضجيج بلا قيمة) |
| د9 | عرض سجل الحقول | داخل **تقرير ملف الموظف** (قسم مطبوع مع الباقي) — لا شاشة جديدة | تبويب مستقل في الشل |
| د10 | الموظفون الخارجيون | يُسمح بتكليفهم وتخصيصهم كالداخليين (تكلفة تعاقدية تظهر على العقد) — بلا استثناء خاص | استثناء الخارجيين (يفقد العقد جزء التكلفة الحقيقية) |

## 3) المخطط (Prisma) — حقل واحد + 5 جداول جديدة

### 3.1 توسعة القائم
```prisma
model Employee {
  // القائم كاملًا يبقى — إضافة واحدة:
  monthlyCostRate Decimal @default(0) @map("monthly_cost_rate") // د2 — 0 ⇒ افتراضي الراتب الأساسي عند التخصيص
}
// علاقات مرجعية عكسية على: Employee (assignments/auditLogs/teamMemberships/laborAllocations)
// Contract (employeeAssignments/laborAllocations) — PayrollBatch (laborAllocations)
```

### 3.2 الجداول الخمسة (كلها companyId + تُضاف إلى TENANT_MODELS/BACKUP_MODELS بنفس الـcommit — درس T111)
```prisma
model EmployeeAuditLog {      // د9 — NovaFlow employeeAuditLogs معرفيًا
  employeeId Int, field String        // اسم الحقل المعرفي (salary)
  fieldLabel String                   // العنوان العربي لحظة الكتابة (لقطة)
  oldValue String @default(""), newValue String @default("") // نصيًا منسقًا
  editedBy String, editedAt DateTime
  @@index([employeeId, editedAt])     // @@map("employee_audit_logs")
}

model WorkTeam {              // د6 — فريق تشغيلي
  name String, active Boolean @default(true), notes String @default("")
  @@unique([companyId, name])         // @@map("work_teams")
}

model WorkTeamMember {
  teamId Int (Cascade), employeeId Int (Cascade)
  @@unique([teamId, employeeId])      // @@map("work_team_members")
}

model EmployeeAssignment {    // مرآة EngineerAssignment حرفيًا
  employeeId Int, contractId Int, role String @default("")
  allocationPct Decimal @default(100) // النسبة الافتراضية للتوليد
  startDate String @default(""), endDate String @default("")
  status String @default("سارية")     // سارية | منتهية
  notes String @default("")
  @@index([employeeId, status]) @@index([contractId])   // @@map("employee_assignments")
}

model LaborAllocation {       // سطر التوزيع الشهري المجمّد — د1: تحليلي بلا قيد
  batchId Int (Cascade), employeeId Int, contractId Int
  sharePercent Decimal                // نسبة شهر تكلفة الموظف
  snapMonthlyRate Decimal             // لقطة التكلفة لحظة الكتابة (Cost Snapping)
  amount Decimal @db.Decimal(18,3)    // = rate × share% مجمّد
  note String @default(""), createdBy String @default("")
  @@unique([batchId, employeeId, contractId])           // @@map("labor_allocations")
  @@index([contractId]) @@index([batchId])
}
```
ملاحظة: `contractId` في `LaborAllocation` **إلزامي** — «غير الموزع» لا يُخزَّن، يُحسب: `rate×100% − ∑ الأسطر` (مقياس تغطية لكل موظف ولكل دفعة).

## 4) قواعد التكليف والتخصيص (النواة النقية `hr-labor-core.ts`)

- **التكليف**: موظف × عقد × نسبة (0 < pct ≤ 100) + فترة اختيارية + حالة سارية|منتهية. إعادة إسناد لنفس الزوج بنفس الفترة السارية = تحديث للسطر (لا تكرار). الحذف حر (لا ربط مالي) مع audit.
- **التوليد الآلي للتخصيصات** (`buildAllocationPlan`): لكل موظف له سجل في الدفعة — اجمع تكليفاته **السارية** لحظة نهاية شهر الدفعة، ولقطات: `rate = monthlyCostRate || salary`، `amount = r3(rate × pct ÷ 100)`؛ فشل إن `∑ pct > 100` لموظف (د7 — رسالة بالاسم)؛ تخطٍّ للموظف بلا تكليفات (يظهر «غير موزع»).
- **التحرير اليدوي**: إضافة/تعديل/حذف أسطر التخصيص حتى التجميد (د5) — تحذير ظاهر عند `∑ share < 100%` (غير موزع) دون منع؛ منع share ≤ 0 أو > 100 للسطر الواحد.
- **غير الموزع**: KPI بالدفعة `∑rate − ∑amount` وبالقائمة «موزع من أصل تكلفة الشهر».
- **القراءة التقاريرية**: تخصيصات الدفعات `approved|paid` فقط — الملغاة شفافة.

## 5) تكلفة العمالة في تقارير العقود (د4 — إضافات بلا مساس)

- **تقرير الربحية** (`api/reports/profitability`): استعلام ثالث — `laborAllocations` حيث `contractId ∈ ids` ودفعة `approved|paid` مجمّعة بالعقد ⇒ عمود `laborCost` + `comprehensiveProfit = actualProfit − laborCost` + في المجاميع.
- **نظرة العقد** (`api/contracts/[id]/overview`): سطر «تكلفة العمالة (مخصصات مساير معتمدة)» + قائمة الموظفين المخصصين بنسبهم.
- **بطاقة المسير** (HRView): شارة «التوزيع: X من Y» + زر «توزيع التكلفة» يفتح حوار التخصيص (توليد آلي + شبكة تحرير + سطر غير موزع) — للدفعات غير المدفوعة.

## 6) تدقيق الملف حقلًا-بحقل (د8/د9)

- **نقطة الخَطّ الواحدة**: `PATCH api/hr/team/[id]` — قبل التنفيذ تُبنى الدفعة بنواة `diffEmployeeFields(before, after, formatter)` فتُكتب أسطر `EmployeeAuditLog` في نفس الـtransaction، ثم سطر التدقيق العام القائم كما هو (طبقتان بلا ازدواج).
- **الحقول المتعقوبة (قائمة مغلقة معلنة في `hr-constants`)**: name · active · employeeType · paymentBasis · salary · dailyRate · monthlyCostRate · department · jobTitle · nationality · civilId · hireDate · phone · paymentMethodId · notes — بتسميات عربية ثابتة `EMPLOYEE_FIELD_LABELS` ومنسّق قيم (نشط/موقوف · شهري/يومي · أسماء وسائل الدفع).
- **الحذف والإنشاء**: يبقيان في التدقيق العام + PurgeAudit القائمين (د8) — لا أسطر حقول لهما.
- **العرض**: قسم «سجل تغييرات الملف» في تقرير ملف الموظف (آخر 100 سطر تصاعديًا، مطبوع) + عدّاد تغييرات بجوار الموظف في قائمة الموظفين.

## 7) الواجهة والشل والصلاحيات

- **الشل**: بند HR يزداد بندًا واحدًا بعد «نهاية الخدمة» وقبل «التقارير»: **«الأطقم والتكليفات»** (Network) — `section: "labor"` — `perm: screen_hr` (إخفاء تلقائي عبر navModulesFor).
- **قسم «الأطقم والتكليفات»** (HRView): ثلاث مناطق بنمط القائم:
  1. **الأطقم**: بطاقة فريق (اسم + أعضاء بأداة اختيار الموظفين + ملاحظة) + أزرار «تكليف جماعي بعقد» تفتح حوار (عقد + دور + نسبة + فترة) تولّد تكليفًا لكل عضو.
  2. **التكليفات**: جدول بفلاتر (موظف/عقد/حالة) + إضافة يدوية + إنهاء (منتهية) + حذف — كل حركة audit.
  3. **توزيع شهر**: اختيار دفعة غير مدفوعة ⇒ زر «توليد من التكليفات» + شبكة أسطر (موظف·عقد·نسبة·مبلغ اللقطة) + سطر «غير موزع» الملون — نفس حوار «توزيع التكلفة» من بطاقة المسير.
- **حوار الموظف**: حقل جديد «التكلفة الشهرية على الشركة» (اختياري — placeholder «افتراضي: الراتب الأساسي»).
- **تقرير الربحية**: عمودا «تكلفة العمالة» و«الربح الشامل» (ديسكتوب) وبصف موسّع بالجوال.
- **ملف الموظف**: قسمّا «التكليفات» و«سجل تغييرات الملف» ضمن الطباعة القائمة.
- **الصلاحيات**: بلا مفاتيح جديدة — `screen_hr` يغطي كل مسارات `api/hr/labor/*` خلف `moduleGuard("hr")`؛ تقرير الربحية ونظرة العقد بصلاحياتهما القائمتين؛ audit على كل حركة.

## 9) خطة التنفيذ والاختبارات (بعد الاعتماد)

1. **السكيما**: حقل Employee + 5 جداول + علاقات عكسية + `db:push` + TENANT/BACKUP بنفس الـcommit.
2. **النواة النقية + الاختبارات**: `EMPLOYEE_FIELD_LABELS` + المنسّق في `hr-constants.ts` + `hr-labor-core.ts` (plan/validate/amounts/diff) — ملف اختبار قبل أي ربط.
3. **الخادم**: `api/hr/labor/{teams,assignments,allocations(+generate)}` + خَطّ التدقيق في PATCH الموظف + توليد الدفعات يظل كما هو (التخصيص منفصل عنه عمدًا) + توسعة profitability وoverview وreports/employee.
4. **الواجهة**: الشل + قسم labor + حوار التوزيع بالمسير + عمودا الربحية + حقل التكلفة + قسمّا الملف.
5. **تحقق حي** (شركة بذر ثم تنظيف كامل): موظفان بتكلفة 900/1200 ⇒ فريق عضوان ⇒ تكليفات 100% و40/60% (فحص سقف: تكليف ثالث 70% ⇒ رفض عربي) ⇒ مسير نوفمبر معتمد ⇒ توليد التخصيص (900·480/720 — لقطة تتحقق) ⇒ الربحية: عقد أ عمالة 1380 وربح شامل صحيح، غير موزع 0 ⇒ موظف بلا تكليفات يظهر غير موزع ⇒ تعديل راتب ⇒ سطر تدقيق (قديم→جديد) بالملف المطبوع ⇒ دفع المسير ⇒ التخصيصات للقراءة فقط ⇒ موبايل 375 بلا تمرير أفقي ⇒ تنظيف شامل (صفر جداول خمسة وصفر حقول).
6. **push ومراجعة الإنتاج** — النشر التلقائي عبر main.

## 10) حدود HR-3 (ما لا يُبنى عمدًا)

- بلا مراكز تكلفة محاسبية ولا قيود تحويل (د1) — التخصيص لا يدخل القوائم المالية ولا الزكاة ولا iXBRL ·
- بلا تخصيص على مستوى **مرحلة** العقد (مستوى العقد فقط — المراحل عند طلب فعلي) · بلا ساعات فعلية من الحضور في التخصيص (د3) ·
- بلا تكاليف معدات/مواد/إهلاك للأطقم (عمالة فقط) · بلا تعرفة ساعية (شهرية تُقسم داخليًا عند الحاجة) ·
- بلا تصدير XLSX جديد (طباعة المتصفح تكفي) · بلا إشعارات/تطبيق موبايل/توظيف (حدود HR-2 باقية) ·
- بلا جدول تعرفة مؤرّخ منفصل (د2 — التاريخ عبر تدقيق الحقول).

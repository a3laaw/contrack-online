# تصميم «التنفيذ الميداني — مقايسة التنفيذ» — بند NOVA 5

> **المصدر:** docs/novaflow-study.md §6 L122 («مقايسة كميات ببنود بـ6 عدادات: تعاقدي/مخطط/تغييري/منفذ/موثق/مفوتر»)
> وL125 (زيارات ميدانية بشبكة رباعية + صور + GPS + ربط ببنود المقايسة) وL126–L128
> («executions ترفع العدادات · أوامر تغييرية تضيف كميات دون لمس الأصل») ودرس G9 (L150).

## 0) القرار الجوهري — كل العدادات **مشتقة لا مخزنة** (G9)
درس NovaFlow G9: عدادات تنفيذ تتقدم من مسارات متعددة بلا أداة recount — أي حذف يدوي يفسد الأرقام.
قرارنا: **لا عدّاد مخزّن إطلاقًا**. المقايسة تُشتق لحظيًا من صفوف `field_executions` وبنود `boq_items`
وملاحق معتمدة — الحذف/التعديل آمن دائمًا لأن الاشتقاق من الصفوف يعيد الاحتساب تلقائيًا
(recount مدمج بالتصميم، لا أداة خارجية).

## 1) مصادر العدادات الستة (counter-sources)
| العداد | المصدر (اشتقاق لحظي) |
|---|---|
| تعاقدي | `max(0, qty − changeQty)` — كمية البند الفعلية مطروحًا منها نصيبها من الأوامر التغييرية المعتمدة (أرضية صفر) |
| مخطط | عمود جديد `planned_qty` على `boq_items` (إدخال يدوي عند التخطيط — قد يتجاوز الفعلي بقصد، لا يُقص) |
| تغييري | Σ كميات أجزاء الملحقات **المعتمدة** (side=client, action=add, refKind=boq) المرتبطة بالبند |
| منفذ | Σ سجلات التنفيذ الميداني للبند (`field_executions.qty`) |
| موثق | Σ سجلات التنفيذ المعلَّمة `documented=true` (توثيق مهندس الموقع) |
| مفوتر | على مستوى العقد حصرًا: Σ فواتير غير ملغاة (Σ total) والمحصّل Σ paidAmount — الربط بالبند لاحق (حد موثق بالتصميم) |

### 1.1 القاعدة المطبقة لعداد «تغييري» (بعد قراءة approveAddendumTx حرفيًا)
اعتماد الملحق (`approveAddendumTx` في addendum-server.ts) **لا يزيد كمية بند قائم أبدًا**:
جزء `add boq` ينشئ BoqItem جديدًا ويسجّل `boqItemId = createdItemId = refId = id البند المنشأ`،
والحذف `delete boq` حذف ناعم كامل للبند. لذلك قاعدتنا:
`تغييري(بند) = Σ qty` لأجزاء `action=add, refKind=boq` من ملحقات عميل **معتمدة** حيث
`boqItemId == id البند` أو `createdItemId == id البند` — وبعد التطبيق هما متطابقان فتُحسب **مرة واحدة**
(وحارس `refKind=boq` يمنع التصادم مع أجزاء plan التي يحمل createdItemId فيها معرف دفعة لا بند).
النتيجة: البند المنشأ بملحق كميته كلها «تغييرية» ⇒ تعاقديه = 0، والبند الأصلي لا يُلمس أصلًا —
مطابق حرفيًا لمبدأ «أوامر تغييرية بلا لمس الأصل» (L128).

## 2) المخطط
- `boq_items.planned_qty Decimal @default(0)` — عداد «مخطط» (يُدخل من شاشة بنود الكميات).
- جدول `field_executions` (موديل `FieldExecution`): عقد + بند + تاريخ + كمية(18,3) + موثق +
  GPS (نصان) + مرفق صورة واحد (`attachmentId` → contract_attachments) + ملاحظة + منشئ.
- تسجيلات T111 في نفس الcommit: `TENANT_MODELS` (db.ts) + `BACKUP_MODELS` (backup-dump.ts،
  بعد contract_attachments لارتباط attachment_id) + خطوة حذف في الإعادة الكاملة قبل boq_items
  (FK boq_item_id Restrict — درس T111).

## 3) الحدود الموثقة (ما لا يُبنى الآن)
- لا شبكة رباعية لأطقم العمل (موظفون/عمالة/معدات/مواد) — تحتاج كيانات HR workGroups: بند مستقبلي.
- لا إقفال مراحل كمّي آلي (numericTarget) — إغلاق المراحل يبقى يدويًا كما هو.
- الصور عبر مرفقات العقود القائمة (POST /api/attachments) — مرفق واحد لكل سجل تنفيذ.
- لا نافذة تعديل للسجل في الواجهة (G3/G5) — التصحيح = حذف + إعادة إضافة، والعدادات تُشتق من جديد.

## 4) النواة والمسارات والواجهة
- `src/lib/field-execution-core.ts` — نواة نقية: اشتقاق صف المقايسة، تحقق إدخال السجل،
  `GPS_RE`، ومجاميع المقايسة. نسبة التقدم تُحسب كما هي وقد تتجاوز 100% عند التنفيذ الزائد —
  إشارة حقيقية لا خطأ (الاشتقاق لا يخفي)، والمسار كذلك.
- `GET /api/contracts/[id]/takeoff` — المقايسة المشتقة (بنود + مجاميع + آخر 15 سجل تنفيذ) —
  حارس `screen_contracts` كجوارها.
- `POST/PATCH/DELETE /api/contracts/[id]/executions` — سجل التنفيذ (حارس `action_edit_contract`،
  حدث عقد «تنفيذ ميداني/تعديل تنفيذ ميداني/حذف تنفيذ ميداني» + audit داخل المعاملة).
- قسم ⑥ «📐 التنفيذ الميداني» في صفحة الدفعات: جدول المقايسة + شارات المجاميع + سجل التنفيذ
  (آخر 15) + نافذة تسجيل (تاريخ/كمية/موثق/GPS مع «📍 التقاط الموقع»/صورة/ملاحظة)،
  والأزرار الحساسة تُبصّر للمدير كما تفعل أقسام بنود الكميات في نفس الملف.

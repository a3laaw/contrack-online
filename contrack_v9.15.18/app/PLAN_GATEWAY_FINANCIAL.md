## ١. منطق T+1 للبوابة والتحويل البنكي

### المشكلة
الآن الدفعات عبر البوابة (KNET) أو التحويل البنكي تُسجل بنفس تاريخ الدفع.但实际上 الشركة تتلقى المبلغ في **اليوم التالي** مع تخطي أيام الإجازة.

### الحل
```python
# services/settlement_service.py — تُضاف دالة جديدة

def effective_date(payment_date: str, method: str) -> str:
    """تاريخ الاستحقاق الفعلي للدفعة.
    
    - بوابة / تحويل بنكي → اليوم التالي (T+1)
    - يُتخطى الجمعة (4) والسبت (5)
    - نقدي / شيك → فوري (نفس اليوم)
    """
    from datetime import date, timedelta
    if method not in ("بوابة", "تحويل بنكي", "KNET", "بنك"):
        return payment_date  # نقدي / شيك = فوري
    d = date.fromisoformat(payment_date)
    d += timedelta(days=1)
    while d.weekday() in (4, 5):  # الجمعة + السبت
        d += timedelta(days=1)
    return d.isoformat()
```

### أين يُطبّق
| المكان | التأثير |
|--------|---------|
| `settlement_service.py` → `save_gateway_ops()` | عند حفظ عمليات البوابة: يُسجل `effective_date` |
| `other_company_page.py` → التقرير | يعرض العمليات بتاريخها الفعلي (T+1) |
| `report_service.py` → `cash_flow_report()` | يحسب الداخل من البوابة بتاريخ T+1 |

### التعديلات المطلوبة
1. إضافة عمود `effective_date` لجدول `gateway_ops` (migration)
2. دالة `effective_date()` في `settlement_service.py`
3. تعديل `save_gateway_ops()` لحساب `effective_date` تلقائيًا
4. تعديل عرض التقرير في `other_company_page.py` ليعرض `effective_date` بدل `date` للبوابة

## ٢. التقرير المالي الشامل

### المعادلة
```
الرصيد الفعلي (البنك) =
    الرصيد الافتتاحي
  + تحويلات البوابة الواردة (بسعرها الفعلي يوم T+1)
  + سندات القبض (نقدي + شيك)
  − مصروفات البنك (رواتب + موردين + تشغيلية)
  − سلف الموظفين (غير المسترجعة)

الرصيد الدفتري =
    الرصيد الافتتاحي
  + جميع الإيرادات المسجلة
  − جميع المصروفات المسجلة
  − سلف الموظفين (غير المسترجعة)

الفرق (تعادل بنكي) =
    مدفوعات بوابة في الانتظار (T+1 لم يحن بعد)
  + شيكات مؤجلة
  + فروقات أخرى
```

### ما هو موجود بالفعل
- `report_service.py` → `cash_flow_report()` — يحسب الداخل/الخارج/الرصيد التراكمي
- `report_service.py` → `expenses_report()` — يحسب المصروفات (ويستبعد سلف الموظفين)
- `settlement_service.py` → `other_balance()` — يحسب مستحق/مسدد/متباقي للشركة الأخرى

### ما يجب إضافته
1. **ربط البوابة بالتقرير المالي:** الداخل يشمل مدفوعات البوابة بتاريخ T+1
2. **إضافة سلف الموظفين للمصروفات:** تظهر كبند منفصل في التقرير
3. **حساب الرصيد الفعلي vs الدفتري:** مع عرض الفرق (تعادل بنكي)

### الملفات
| الملف | التعديل |
|-------|---------|
| `services/report_service.py` | تعديل `cash_flow_report()` ليشمل البوابة بـ T+1 + سلف الموظفين |
| `ui/financial_report.py` | واجهة جديدة تعرض الرصيد الفعلي + الدفتري + الفرق |

## ٣. سلف الموظفين

### ٣.١ قاعدة البيانات
```sql
CREATE TABLE IF NOT EXISTS employee_advances (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    employee_id     INTEGER NOT NULL REFERENCES employees(id),
    amount          REAL NOT NULL,
    advance_date    TEXT NOT NULL,
    reason          TEXT DEFAULT '',
    status          TEXT DEFAULT 'نشطة',     -- نشطة / مسترجعة / ملغاة
    repaid_amount   REAL DEFAULT 0,
    repaid_date     TEXT DEFAULT '',
    payment_method  TEXT DEFAULT 'نقدي',
    notes           TEXT DEFAULT '',
    created_at      TEXT DEFAULT (datetime('now','localtime'))
);
```

### ٣.٢ القواعد المحاسبية

| الحدث | المصروفات | البنك | الإيرادات |
|-------|-----------|-------|-----------|
| **صرف سلفة** | ✅ تُضاف | ✅ تُخصم | ❌ لا تأثير |
| **استراجع كامل** | ✅ تُحذف | ❌ لا تأثير | ❌ **لا تُ计入** |
| **استراجع جزئي** | ✅ يُطرح المبلغ | ❌ لا تأثير | ❌ لا تأثير |
| **إلغاء** | ✅ تُحذف | ❌ لا تأثير | ❌ لا تأثير |

> **مهم:** الاستراجع **ليس إيراد** — هو إرجاع مال مُسلَّف، لا يدخل في الإيرادات أبدًا.
